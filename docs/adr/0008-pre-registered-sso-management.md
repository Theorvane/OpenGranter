# Pre-registered SSO identities and API access tokens

The contributor selected administrator-pre-registered issuer/subject bindings and API-specific SSO JWT access tokens for the first human-only management API on 2026-10-11. This trades automatic first-login onboarding and browser session state for explicit identity enrollment and an API authentication boundary; changing it later would change provisioning and client login flows. They subsequently selected the RFC 9068 access-token profile over an unspecified provider-specific format, accepting that nonconforming IdP tokens need a later explicit profile. SSO identity supplies no IAM bypass. They also confirmed administrator-managed RS256 public keys, a maximum one-hour lifetime/age with 60-second tolerance, and required auth_time, accepting manual key deployment and rejection of tokens without end-user authentication context. Its meaning remains a trusted issuer guarantee; public HTTP authentication/audit remains separate.
