## Management listener composition boundary

Public issue/revoke handlers exist, but default `npm start` does **not** activate their listener: [service](../src/gateway/gateway-service.ts) starts `startPostgresDualRouteGateway`. [Runtime](../src/gateway/postgres-gateway-runtime.ts) exposes separate `startPostgresSsoManagementGateway`; bootstrap requires `openConnection`, `resolveSecret`, `checkLimit`. Ingress alone does not install management HTTP. R1 must assign listener startup/configuration, bind/exposure isolation, dependency injection, health/failure handling and graceful shutdown ownership before installed readiness is claimed.

Developer/service-account gateway paths do not replace platform/team administrator and auditor browser journeys. Team-administrator scope remains undecided, not inherited global access.

## Ordered next contracts

1. **R1 browser boundary:** choose same-origin server session/BFF versus deliberately designed OIDC client. Specify issuer/audience/keys, callback/redirect allowlists, state/nonce/PKCE, session lifetime/revocation, CSRF/CORS, ingress, no-store and errors before coding. Never put SSO/proxy secrets in URLs, browser persistence or logs. Define login/logout, expired-session, denial and current-principal tests. Specify browser-session to trusted SSO bearer actor propagation without weakening RFC9068 validation; define current-principal response, permission freshness and disabled-principal propagation. Proxy-authenticated usage/audit needs a separate browser authorization boundary. Own management-listener lifecycle as above. Settle first-administrator bootstrap, issuer/subject binding registration/revocation authority, post-bootstrap disable/recovery, self-escalation denial and change audit; these remain unapproved decisions, not defaults.
2. **R2 management authority:** reuse fresh persisted evaluation and owner-scoped `iam:Manage` where applicable. Specify principal/role/policy CRUD, delegated scopes, concurrency and required atomic mutation audit. Do not expand token-owner iam:Manage checks into blanket role/policy CRUD authority. Specify mutation/audit atomicity, version conflicts and policy change/deletion visibility; simulator caller/target scope, output access and access audit. Simulator output does not authorize execution.
3. **R3 catalog/routing/limits:** separate discovery from mutation. Specify `catalog:Manage` resources, secret references, versioned prices, route kinds and budget/limit decisions before writes. Split independent catalog CRUD from unresolved monthly limits and managed-routing scoring. Specify secret-reference destination/registration/read/rotation permissions; block only dependent functionality.
4. **R4 review:** reuse scoped reader/filter/CSV contracts through explicitly authorized browser boundary. Implement loading/error/denial/empty states. Read-only UI may proceed in parallel after R1 authentication and scoped-reader authority are settled; it is not the final product. Track monthly limits, managed routing, content audit and #7 separately; do not silently settle them through UI work.
5. **R5/R6:** reconcile compatibility backlog, then installed browser/gateway/security/usage/restart acceptance using approved credentials/client/model and maximum paid budget. No automatic paid fallback.
