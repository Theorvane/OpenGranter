# RFC 9068 SSO token management

## Issue and problem

- Issue [#488](https://github.com/Theorvane/OpenGranter/issues/488). #486 supplies exact SSO bindings, but no real JWT verifier or internal composition derives the management actor without caller nomination.
- The contributor confirmed RFC 9068, administrator-registered issuer/API audience and RS256 public JWKs, a one-hour maximum access-token lifetime/age with 60-second clock tolerance, and required signed auth_time on 2026-10-11. The issuer must use auth_time only for actual end-user authentication. These choices expanded this issue before production code.

## Scope and expected behavior

- Implement a real TypeScript verifier using pinned jose, local administrator public keys and no discovery/network. Require the RFC claims iss/sub/aud/exp/iat/jti/client_id plus local auth_time; enforce exact issuer, API audience membership, RS256 signatures and at+jwt media typing. Output only a frozen verified issuer/subject.
- Require nonnegative finite NumericDates, exp > iat, exp-iat <= 3600 seconds and auth_time <= iat. Optional nbf must precede exp. Enforce time since iat <= 3600 with 60-second tolerance, future iat/nbf within that tolerance and expiry with the same tolerance. auth_time may predate a refresh: no additional login-freshness requirement is implied.
- Local bounds: compact token 1–16384 UTF-16 units, issuer 1–2048, subject/client_id/jti/API audience/key IDs 1–256, audience arrays at most 64, public keys 1–16. Strings exclude NUL/ill-formed Unicode. Configured issuer is HTTPS without userinfo/query/fragment/whitespace and stays exact. Keys are canonical public RSA JWKs with unique IDs, 2048–4096-bit moduli, allowed signing/verification metadata and no private/unknown own members. These are explicit local restrictions.
- Add internal PostgreSQL issue/revoke composition. Capture own required operation fields once before asynchronous work; verified identity resolves a current active human binding before existing fresh IAM/token management. Ignore forged actor/policy/owner/claim fields. Metadata IDs are 1–256; operation expiry remains a nonnegative safe integer.
- Preserve implicit/explicit Deny, owner-scoped iam:Manage, required decision audit before mutation, 30/90-day proxy-token caps and atomic lifecycle events. No authentication cache; reverify each operation. No raw access token/issuer/subject in decisions/lifecycle/errors. Failed authentication appends no token-management decision with an unreliable actor.
- No public HTTP authentication/endpoint/audit contract, automatic JWKS fetch/rotation, introspection/replay/revocation cache, binding/account provisioning, schema migration, inference or usage change.

## Design

- createRfc9068SsoAccessTokenVerifier({ issuer, audience, jwks, now }) snapshots own configuration and public keys before returning verifyAccessToken. Use jose local JWKS/jwtVerify with RS256, type/issuer/audience/required-claim/max-age/skew options; validate custom claim types, bounds and temporal relationships explicitly. Signature/token rejections return undefined; clock/unexpected failures throw safe SsoAccessTokenVerificationUnavailable. Invalid configuration throws InvalidSsoAccessTokenConfiguration without private data/cause.
- createPostgresSsoTokenManagementService({ client, now, verifyAccessToken }) accepts only a trusted verification port. createPostgresRfc9068SsoTokenManagementService wires the real verifier from administrator configuration. Both expose issue({ accessToken, requestId, principalId, expiresAt }) and revoke({ accessToken, requestId, credentialId }), deriving authenticatedActorId internally.
- Invalid inputs throw InvalidSsoTokenManagementInput before verifier/SQL. Verification rejection/missing/inactive/service binding throws SsoManagementUnauthenticated. Malformed verifier claims, verifier/binding throws and dependency failures throw SsoManagementAuthenticationUnavailable. Never trust a thrown verifier error's name or preserve its cause. Existing later management errors retain their safe denial/availability contracts.
- Reuse existing IAM/audit/credential components. Configuration snapshots require a rebuilt verifier for manual key changes; overlap old/new registered keys for rotation. Binding and policy reads are separate; later/intervening state changes are not transactionally revalidated.
- [RFC 9068](https://www.rfc-editor.org/rfc/rfc9068.html#section-2.2) makes auth_time optional and client_credentials subjects normally identify applications. Required auth_time is a confirmed local restriction depending on trusted issuer semantics, not universal human-grant proof. [RFC 8725](https://www.rfc-editor.org/rfc/rfc8725.html#section-3.12) requires separate token validation rules. [jose local keys](https://github.com/panva/jose/blob/main/docs/jwks/local/functions/createLocalJWKSet.md) and [claim options](https://github.com/panva/jose/blob/main/docs/types/interfaces/JWTClaimVerificationOptions.md) support the chosen flow. Type comparison follows media-type case/application-prefix semantics.
- Update [PRD](../PRD.md), [architecture](../architecture.md), [acceptance](../acceptance.md), [SSO foundation](../../contracts/sso-management-foundation.md), [token management](../../contracts/token-management.md), [composition contract](../../contracts/sso-token-management.md), [JWT contract](../../contracts/sso-access-tokens.md), [CONTEXT](../../CONTEXT.md), [ADR0008](../adr/0008-pre-registered-sso-management.md) and [compatibility inventory](../openrouter-compatibility.md). Public HTTP/authentication audit and audited provisioning remain explicit separate work.

- The configured management factory also requires and captures its five own settings once, ignores extra authority, and sanitizes constructor/getter failures. JWT temporal checks use jose whole-second current-time granularity; fractional NumericDates remain supported.

## Verification evidence

Valid SSO access tokens can now drive internal proxy-token issue/revoke without letting a caller nominate the authenticated actor. A real RFC 9068 verifier uses administrator-registered RS256 public JWKs, exact issuer/API audience, required claims and auth_time, a maximum one-hour lifetime/age and 60-second tolerance. Its frozen verified issuer/subject resolves only to a current pre-registered active human; the existing service then reloads IAM and retains owner-scoped iam:Manage, explicit/default Deny, required decision audit, 30/90-day owner caps and atomic credential lifecycle writes.

Configuration/key and operation fields are captured once; raw tokens/SSO claims stay out of fixed errors and management records. Header keys/URLs cannot select trust or trigger network access. Both injected and configured factories reject authentication/dependency failures before management. The new exact production dependency is jose 6.2.12; private signing keys and synthetic tokens are generated only in test memory.

Validation:
- Behavioral red: `node --experimental-strip-types --test test/sso-access-tokens.test.ts test/sso-token-management.test.ts` against deny-only typed exports failed 134 of 190 tests for missing valid verification/composition and missing input/config/clock errors (56 expected denials passed). An initial signing-fixture prevalidation problem was corrected before this red run; it is not counted as verifier evidence.
- Configuration-boundary red: the configured factory tests failed 7 of 89 cases before own-setting validation and sanitized constructor failures (82 existing cases passed).
- Green: the focused verifier/composition suite passes 200 tests, including real runtime-signed tokens through all migrated PostgreSQL stores, denial/failure paths, mutations, private records, time bounds, and crypto-key-import failure.
- Focused V8 coverage: both new production modules have 100% line/function coverage; the composition has 100% branch coverage and the verifier 99.11% branch coverage. Existing reused modules retain their broader suites.
- Final `npm run check`: 6,393 passed, zero failed, one existing opt-in real PostgreSQL test skipped locally; typecheck/lint/document-link-contract-secret scans and all three pinned OpenRouter integrity checks pass. Both repository CI jobs additionally gate merge, including the disposable real PostgreSQL service.
- `npm audit --omit=dev`: zero known production dependency vulnerabilities at verification time. `git diff --check` passes. Existing migrations and all three OpenRouter pins are byte-identical to the base.

Limits: this is an internal authentication/management composition, not public login or a management HTTP route. The registered issuer must emit auth_time only for actual end-user authentication; this local restriction is not universal human-grant proof. Automatic/network JWKS rotation, introspection/access-token revocation/replay protection, public authentication-error/audit contracts and audited administrator provisioning remain separate. Manual key changes require a rebuilt verifier. Binding/policy reads are separate; later concurrent changes are not transactionally revalidated. Existing proxy/inference/discovery/IAM/limit/usage paths are unchanged; full release issue #116 and unresolved Jev issue #7 remain open.
