# Caller-owned versioned flat-token estimates

`captureAttemptUsage` accepts an optional `priceSnapshot` containing `kind: flat-token`, `priceVersion`, ISO-like three-uppercase-letter `currency`, and nonnegative canonical decimal strings `inputPerToken` / `outputPerToken`. This is trusted internal caller data, not provider response content, an HTTP option, discovery price import or a new configuration authority. The caller must select an applicable immutable version at attempt start, including its route/model and pricing terms. Flat aggregate pricing cannot represent cached/reasoning/modality/request/tier discounts or surcharges; do not supply this snapshot for such pricing. Effective time/currency conversion/rounding/budget decisions are not introduced.

`estimateUsageCost` returns the exact sum of prompt and completion counters multiplied by their per-token rates, carrying currency and priceVersion. No floats, per-million implicit units or invoice claims. Snapshot fields are captured once, decimals are bounded to 128 characters, version to 256 UTF-16 units without controls; malformed supplied snapshots evaluated for successful attempts raise fixed `InvalidUsagePrice` without private causes. Absent snapshots, non-reported usage, incomplete/invalid counters and representational overflow return null. Actual reported zero counters or rates produce exact zero. Failed attempts never acquire an estimate from a success-looking response. Unknown usage is not zero usage. Existing `upstreamBilledCost`, comparison semantics, duplicate flags, ledger keys and JSON/CSV columns are unchanged.

This implements the internal estimate-to-attempt recording path only. Catalog price CRUD, automatic gateway price selection/capture, reported-bill collection, reconciliation and live installation remain separate gaps. No active runtime caller supplies prices yet.
