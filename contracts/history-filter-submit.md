# Native history form submission (#642)

- A named History filters form has one Apply filters submit button. Enter in each text input uses the same validation and fresh authorized read as mouse activation. Neither submission navigates the page or serializes private filters into its URL.
- A click prevents its native submit default to avoid a duplicate read; a direct submit event also prevents navigation before checking the existing generation and identity-lifetime guards.
- Invalid page sizes/time ranges/request IDs do not send network requests. Exact supported Unicode model/principal values are preserved; request IDs retain their existing ASCII contract.
- Detached forms after a render, denial or disposal cannot apply filters. Reset and other buttons do not submit. No new authority, endpoint, billing or retention semantics.
- Native synthetic loopback acceptance is distinct from installed authentication, PostgreSQL, company SSO and paid-provider E2E.
