# Function tool cache control contract

Issue #446. Plan: [446-function-tool-cache-control](../docs/plans/446-function-tool-cache-control.md).

Both /v1 and /api/v1 accept optional non-null cache_control={type:"ephemeral",ttl?:"5m"|"1h"} on the outer portable function-tool wrapper, alongside type/function. Delegated OpenRouter forwards it; managed Anthropic emits it alongside name/input_schema/description/strict on the native tool. Names, descriptions, schema, declared order, supported strict/choice/parallel controls and correlated history keep their prior mappings. Nonstream text/refusal/function responses and function-capable streams share this support. Omission adds no directive, TTL, header or other default.

Capture root array, wrapper and directive type/TTL once before credentials, freezing new records. Null/malformed/non-record/prototype directives, unknown/null TTL or type, extra members, nested function cache fields and server/custom tools reject before route/secret work. Native OpenAI/Gemini tool directives reject before secrets without format substitutions; Gemini's exported converter also rejects instead of silently dropping them. Plain tools remain unchanged. Native Anthropic's nullable extension and source SDK unknown-TTL extensions remain outside this non-null documented subset.

Tool and text block directives share the existing local maximum of four total across the complete prompt. Evaluate tool order first, then instruction/message order, following native tools→system→messages. A 1h directive cannot follow an effective 5m directive; omitted TTL counts as 5m only for this check, without writing a default. Both families may coexist within valid bounds. Reject coexistence with request-level cache_control, root prompt_cache_options or any non-null OpenAI history breakpoint before routes/credentials because mixed-format precedence/conversion remains unverified. Explicit OpenAI marker write/window rules remain independent.

Authentication, complete approved model/final-provider/host IAM/Deny scope, limits, required audit/usage before final delivery, reported-only cache accounting, missing usage and safe possibly-billed failure/cancellation remain shared. Keep private tool/schema/directive data and keys out of operational records/errors and synthetic response echoes. Cache preferences cannot enable content auditing or broaden Jev disclosure; its configured text view remains unchanged. Do not infer model eligibility, hits, prefix retention, savings, usage or provider-billed cost.

The unchanged version-28 pin already selects whole ChatFunctionTool and its directive/cache/TTL targets (32 fields/22 request-history definitions). Offline integrity and fresh fixed-host structural equality remain the gates; local bounds are not invented source constraints. Installed OpenAI 7.23.0 and OpenRouter 1.4.18 sockets exercise controlled requests. The OpenAI SDK forwards this compatible wrapper extension through the gateway; native OpenAI support is not asserted. Tool-marker conversion, server/custom tools, nested fields, mixed automatic/explicit controls, native partial tool-result caching, live certification, full #116 and unresolved #7 remain open.
