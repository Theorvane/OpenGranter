# OpenAI-style exact model retrieval

GET /v1/models/{model} and /api/v1/models/{model} accept one encoded path parameter and return a bare model object, matching that alias's row in the respective listing projection. Legacy output contains id/object/created/owned_by; the compatible base also retains captured published rich metadata when available. Basic aliases work on both bases. This is a separate OpenAI client extension: OpenRouter's singular /api/v1/model/{author}/{slug} retains its wrapped rich-only response.

Resolve only the exact enabled local alias after current model AND final-provider IAM with explicit Deny precedence. Validate/capture the whole catalog, including hidden metadata, before releasing a result. Unknown, disabled, inaccessible, canonical metadata slugs and unpublished alias targets share a fixed404; metadata never redirects or grants lookup/routing authority. Every successful or not-found lookup requires existing model-read audit with count1/0; catalog failures use model-read-unavailable without event-specific details. Required audit failure suppresses output. Existing PostgreSQL projection/history retain attribution and counts only. No new event kind or migration is introduced.

Authenticate before decoding the parameter, checking its query or reading the catalog. Local bounds are4,608 encoded UTF-16 units and512 decoded units. Decode once; encoded slashes may separate components of the exact alias but never create a new HTTP route. Reject empty/dot/dot-dot decoded components, whitespace, C0/DEL/C1 controls and decoded percent/backslash/question/hash. Reject malformed encoding and nonempty queries with400 after authentication and before catalog access. Unsupported methods and literal nested/trailing path segments remain404. No request body is read. URL/proxy normalization can occur before the handler; only preserved SDK-style single-parameter requests are certified.

Existing /api/v1/models/count and the [user collection](user-model-discovery.md) at /api/v1/models/user have precedence over model retrieval. Local aliases named count or user can be retrieved on /v1, but not through those reserved compatible collection paths; alternate encodings of those compatible IDs reject400. These collisions are explicit local compatibility restrictions. A caller must not treat models.retrieve('count') or models.retrieve('user') on /api/v1 as a model read. Existing collection defaults, filters, private audit and response envelopes remain governed by their respective contracts.

Capture the projected row before awaiting required audit so source mutation cannot alter the returned alias, timestamp or metadata. Each request reloads current policy/catalog; no cache validator or conditional request skips these gates. All recognized Fetch/Node outcomes, including safe fallback errors and unsupported methods, use no-store and retain the existing base-specific error format. Do not resolve routes, credentials, upstream models, limits or usage during discovery.

Installed OpenAI7.23.0 socket tests cover both bases and route kinds, exact bare/basic/rich results, slash/variant/Unicode encoding and fresh Deny. Installed OpenRouter1.4.18 regression tests preserve its separate singular operation; shared audit storage/history tests still apply. Existing five OpenRouter structural pins remain byte-identical and do not track this separate OpenAI operation. This is bounded SDK compatibility, not general alias syntax, proxy normalization, live metadata, broader APIs or complete #116 certification. Unresolved #7 remains open.
