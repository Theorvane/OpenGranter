# Bounded inline user image inputs

Both chat bases admit user content arrays combining plain text and image_url parts, preserving exact order, empty text, image-only arrays and supplied name. The inline part has exactly type:image_url and image_url with required url and optional detail:auto/low/high. Preserve omission without a detail default. Non-user images, unknown keys/null/malformed fields, original/unknown detail, inherited image fields and remote/file URLs reject before route resolution.

URL accepts only data:image/png|jpeg|webp|gif;base64,<nonempty canonical standard base64>. Require correct alphabet/padding and round-trip canonical encoding; no whitespace, URL-safe alphabet, MIME parameter, alternate casing or image decoding/format guessing. This validates an encoding, not image pixels or MIME authenticity. Local per-URL budget is524288 UTF-16 units including header; all image URLs across a history total at most786432 units. Image-bearing messages contain at most128 parts. Reject known over-budget prefixes before reading later payloads. Existing1MiB HTTP body limit applies independently, so large valid inline histories can still exceed it.

Public normalization captures fixed array positions and type/URL/detail primitives once; snapshots freeze complete parts, image objects, arrays and messages before async routing/credentials. Invalid first values never retry/coerce into valid later ones. Direct OpenAI and delegated OpenRouter retain the captured wire arrays on nonstream and existing text/refusal/function streams. Preserve exact approved model/provider.only/final-provider scope and fixed provider hosts. No gateway image retrieval, arbitrary-host proxy, local file read, resizing, model capability inference or output-image support is introduced.

Any image history combined with request cache_control, prompt_cache_options, text block directives/breakpoints or marked tools rejects as an explicit local restriction. Existing text/cache/refusal/function history behavior stays unchanged. Issue #468 adds the omitted-detail native subset in [native inline images](native-inline-images.md); unsupported native detail/MIME/count/role/cache combinations still reject before secret resolution and upstream calls. Remote references, broader native mappings, richer/mixed content and image cache controls require follow-up work.

A managed Jev configuration with sendPrompt:true rejects an image history with a safe route-unavailable response before selector credentials/calls. The existing text-only selector projection cannot silently omit image data or invent a multimodal disclosure policy. sendPrompt:false continues metadata-only eligible-candidate selection; neither path grants an unevaluated destination. Jev policy #7 remains unresolved.

Authentication, model/final-provider IAM with explicit Deny, limits, required audit/usage, cancellation/backpressure and possibly-billed upstream/persistence failures stay shared. Inline content, MIME/detail and text stay outside operational events/errors/usage; missing usage remains unknown and images never manufacture counters/cost. Safe streamed failures omit final success/DONE after required persistence fails.

Installed OpenAI7.23.0/OpenRouter1.4.18 sockets verify exact snake/camel wire serialization, nonstream/stream completions and image/function continuations with current Deny. Tests use a tiny fixture PNG, mock fixed upstreams and no live inference. Issue #466 adds the transitive ChatContentImage/ChatContentItems source gate in the [image schema contract](image-content-schema.md), preserving this runtime subset. Live/per-model/native certification remains open under #116, along with unresolved #7.
