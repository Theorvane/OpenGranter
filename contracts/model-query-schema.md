# Supported discovery-query schema drift contract

A separate version-2 pin selects official GET /models operation identity and exactly offset, limit, output_modalities, supported_parameters, context, input_modalities, q and sort parameter objects. Capture query name/location, explicit or omitted required status, schema and all structural serialization/extension fields. Select OpenAPI/document versions. Read inline operation parameters only; missing/duplicate supported names, invalid containers, wrong location, parameter references/content instead of schema, and supported-name inherited parameters fail safely for review. Unselected queries, inherited unrelated parameters, operation editorial metadata and other endpoints are outside detection.

The pin has an exact envelope and exact parameter map, fixed official URL, date, canonical source SHA-256 and canonical structural projection SHA-256. Offline integrity validates shape/selected identities/canonical normalized projection/digest and rejects stale or rehashed malformed maps. It cannot independently authenticate the recorded source digest without that source. Structural source changes compare unequal; selected inline schema references/extensions remain in the projection, while referenced targets are not traversed.

Editorial description/title/example/examples/externalDocs/$comment annotations are ignored. Annotation-named schema properties and literal default/const/enum data remain structural. Parameter array and object-key order are normalized; schema arrays retain their order. The source has optional parameters, offset integer/null minimum0/default0, limit integer minimum1/maximum1000/default500, context integer minimum1, and plain non-null strings for both capability filters. No modality enum/text default, comma-list semantics, identifier length or safe-integer bound is manufactured from prose/local runtime policy.

Existing offline and explicit live compatibility commands check both chat and discovery pins. Both pins validate before a single fixed official HTTPS retrieval, reusing credential omission, redirect rejection, bounded time/body and fixed errors. Check results are separate, nonzero for drift/invalid/unavailable data, content-free, and never write pins. The chat version-30 pin is unchanged. Existing discovery IAM/metadata/continuation, limits/audit/usage and SDK behavior are unaffected.

This guard is partial structural change detection. It does not validate instances/responses, implement new query fields, refresh metadata, infer provider capabilities or certify full external-tool compatibility. Newly required unselected queries and structural changes only in referenced targets remain outside detection. Release #116 and unresolved #7 remain open. See [plan](../docs/plans/458-model-query-schema.md).

The discovery normalizer preserves complete x-* extension literal data, including annotation-named keys inside extension objects. The shared normalizer keeps its legacy mode for all chat callers, so chat canonical projections and runtime behavior remain unchanged. A failing regression initially showed extension description values collapsing to the same empty object; the discovery-only normalization mode preserves their differences.
