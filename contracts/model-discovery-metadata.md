# Trusted model discovery metadata

Published aliases may carry optional openRouterMetadata, persisted as nullable catalog_models.openrouter_metadata JSONB by migration 010. Administrators supply a complete, reviewed informational snapshot for the alias. Missing/null storage needs no backfill and preserves the existing basic listing; the HTTP optional property accepts an object or omission, not null. Do not infer prices, moderation or capabilities from candidates or an upstream response during listing.

The bounded snapshot requires canonical_slug, name, nullable context_length, architecture (nullable modality and input/output modality arrays), pricing (prompt/completion decimal strings), top_provider.is_moderated, supported_parameters, nullable supported_voices, nullable default_parameters, nullable per_request_limits and links.details. Gateway-owned id, created, object and owned_by cannot be supplied/overridden in metadata. Reject unknown keys and partial objects. Optional known decimal price components, nullable top-provider token counts and six numeric default controls are supported. The descriptive, identifier, capability, benchmark and pricing-adjustment extensions below add reviewed optional fields; source shapes outside these contracts remain rejected. Strings and arrays are bounded; token counts are nonnegative safe integers; details links accept credential-free HTTPS absolute URLs or safe root-relative paths under the [details link contract](model-details-links.md) and are never fetched. Exact price spelling is retained. JSONB is object-shaped and capped at 64 KiB in storage.

GET /api/v1/models includes configured snapshots only for enabled aliases passing model AND final-provider IAM. Its total_count is the visible count, and links.next is null for this unpaginated response. /v1 retains the basic payload. Listing calls no secrets, limits, inference or usage ports. Unknown aliases cannot be injected through metadata. Malformed configured metadata invalidates the entire catalog before filtering; SQL route resolution validates the same stored snapshot and also fails safely if it is malformed. Required audit failure suppresses successful output. Nested values are captured once, validated and frozen before audit awaits; metadata appears only in the client response, never operational audit/errors.

The official OpenRouter SDK 1.4.18 deserializes configured rich lists and empty visible lists through actual sockets. Its list return is a page containing result. Compatible offset/limit paging and SDK iteration are supported under the [paging contract](model-list-paging.md); the [filter contract](model-discovery-filters.md), [exploration contract](model-discovery-exploration.md), [output lists](model-output-filters.md) and [input/parameter lists](model-capability-lists.md) define current query behavior. Other query fields remain rejected. Source refresh, metadata management APIs and complete discovery workflows remain release gaps. Unconfigured basic aliases retain explicit SDK validation rejection.

Administrators must review metadata against the actual gateway capabilities and all eligible candidates; no minimum-window/price aggregation rule or refresh policy is inferred. Metadata does not grant routing authority, enforce token limits, authenticate a provider or establish billed cost. See [plan](../docs/plans/228-discovery-metadata.md).

## Filter extension (#456)

The [discovery filter contract](model-discovery-filters.md) now adds bounded singleton output_modalities/supported_parameters/context queries. Apply captured metadata predicates after IAM and before paging; matching authorized totals/continuations preserve accepted filters. Unknown and broader filters remain rejected. Filter-only requests retain full-list behavior.

## Descriptive extension (#476)

Complete snapshots may additionally carry own optional description strings (0..8192 UTF-16 units) and expiration_date/knowledge_cutoff strings (0..256 units) or null. Preserve exact text, blanks, date null and omission; supplied undefined, invalid types or excessive lengths fail the complete snapshot. Dates are informational opaque strings without automatic expiry or routing authority. The [descriptive contract](model-descriptive-metadata.md) defines capture, public/storage/SDK cases and limits. These fields never expand search/order or operational metadata. Existing required fields and the storage cap remain unchanged.

## Identifier extension (#478)

Complete snapshots may carry own optional hugging_face_id and architecture.instruct_type strings or null, and architecture.tokenizer strings. Preserve exact text, future enum values, empty strings, null and omission within 256 UTF-16 units; tokenizer null, wrong scalar types, own undefined and excessive lengths fail safely. The [identifier contract](model-identifier-metadata.md) specifies public/storage/SDK capture and limits. No fetching, tokenization, prompt formatting, query expansion or routing/accounting authority follows from these fields.

## Reasoning and alias extension (#480)

Complete snapshots may carry own optional reasoning and alias_target objects under the [capability metadata contract](model-capability-metadata.md). Preserve validated open effort/null/array shapes and exact target display fields; capture/freeze before asynchronous handoffs. These objects do not apply request defaults, resolve aliases, establish live provider support or alter routing/accounting authority. Local bounds, safe complete-catalog validation and current IAM/audit gates remain explicit.

## Informational benchmarks extension (#482)

Complete snapshots may carry own optional benchmarks with own required design_arena rows and optional artificial_analysis indices under the [benchmark contract](model-benchmark-metadata.md). Preserve finite scores/rates, nullable indices, signed safe ranks, exact bounded labels, empty arrays, duplicate rows and order. Capture/freeze nested values once without reading inherited optional fields or executing supplied iterators. Local field/array limits can still exceed the unchanged aggregate 64 KiB storage cap. These values neither expand queries nor establish freshness, ranking, live capability, routing or billing authority; current complete-catalog, model/provider IAM and required private audit gates remain shared.

## Pricing adjustments extension (#484)

Complete pricing snapshots may additionally carry own optional finite discount and bounded overrides under the [pricing adjustments contract](model-pricing-adjustments.md). Preserve optional exact price strings, finite token/time conditions, open UTC day labels, empty/duplicate rows and order; supplied day arrays require at least one item. Capture own fields and bounded own array indices once and deeply freeze before handoffs. Existing lexical price constraints and complete-catalog/IAM/private-audit gates remain; no conditions/discounts are applied and no ranking/billing authority follows. Field/array bounds can still exceed the unchanged aggregate storage cap.
