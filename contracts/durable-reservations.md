# Durable reservations (#1016 / THE-18)

This opt-in internal boundary implements the six owner-approved policies linked in the plan. It is not a public budget configuration API, a billing guarantee, or an activated gateway.

Admission requires a trusted authenticated principal/policy snapshot, complete eligible bounded candidate set, immutable route/request binding and an administrator-attested maximum liability per candidate. Model, transport-provider and final-provider IAM must all Allow; Default/explicit Deny applies. Every amount is an exact decimal in the policy currency. Missing bounds/policy, expired policy, currency mismatch or insufficient quota/exposure fail closed. Never use catalog prices or token estimates as authority. UTC windows are epoch-aligned by configured positive duration; admitted request count is never refunded. Currency and window duration cannot change while historical state exists; policy version and caps may be explicitly replaced under the same principal lock.

A principal policy row serializes all mutations. Admission counts requests in the current window and sums unresolved holds from every window plus settled debit in the current window. A reservation binds principal, credential, policy versions, route/model/request identity, policy version and candidate bounds. Identical replay observes existing state without another execution token; conflicts fail privately. All mutations and required content-free audit are committed together. A failed or ambiguous commit never grants new inference permission; read/recovery is safe but inference is never replayed.

Attempt start consumes one unused candidate slot, assigns the next existing managed attempt ID, and persists intent before returning permission. An owner token authorizes one execution generation; duplicate start fails. Completion and expiry fence that token. Only slots durably known never entered can release money; started slots retain full liability until authoritative reconciliation. Expiry does not refund request count or release uncertain holds. Recovery closes expired execution permissions and reports outstanding attempt IDs for reconciliation without calling providers.

Handoff validates normalized identity against reservation/intent, then appends via the existing immutable usage ledger and records its handoff marker in one transaction. Exact retries are no-ops; conflicting retries fail. Unknown usage remains unknown, estimates and provider-reported amounts retain their original separate fields, and possibly-billed/duplicate flags are preserved. An estimate or reported amount alone does not release a hold. Reconciliation takes only an evidence identifier; a trusted injected resolver attests final amount/currency for that exact attempt. Resolution failure leaves the hold unchanged. Evidence is idempotent, conflicting evidence fails; an amount above the attested ceiling is recorded truthfully and permanently blocks new admissions pending separate operational remediation.

The service does not implement provider billing collection, evidence authorization UI, automatic inference replay, TTL write-off, production caps or Jev calls. Its authentication snapshot, liability authority, resolver and immutable request binding must come from trusted server composition. PR1007 requires an adapter that persists intent immediately before each provider and routes every usage handoff through this transaction; wiring only its old reserve/complete methods cannot provide these guarantees. HTTP/stream activation remains THE-20.

Fallback permission is separate from usage: a trusted adapter must explicitly attest a retryable failure before upstream response start at handoff. Omission is false, a success cannot grant permission, and replay cannot change the recorded classification. Every earlier attempt must have a durable handoff and this classification before another candidate can start. Prior possible billing requires the next immutable usage record to carry possibleDuplicate. Existing usage_records for a request without a reservation also deny fresh admission. Admission retains the actual quota-policy snapshot and rejects policy drift on identity replay.

Clock observations used for expiry, freshness and window admission are taken after the principal serialization lock is acquired. Attempt intent also retains its known timestamp. For a fenced intent whose original handoff was lost, authoritative reconciliation first appends one immutable recovery record to the existing usage_records source in the settlement transaction: outcome unknown, latencyMs null, actualInferenceProviderId null, missing token usage and null estimated/provider-reported costs, with possiblyBilled true. The known intent time is retained as occurredAt; no provider outcome or duration is reconstructed. Recovery and settlement failures roll back accounting, handoff/audit and hold changes together. A later contradictory original handoff conflicts with that immutable record instead of overwriting it. Known succeeded/failed outcomes still require numeric latency; unknown records reject numeric latency, reported counts, invented bills or a claimed actual provider. Existing JSON exposes the explicit unknown/null pair, CSV leaves unknown latency blank, and record details show Unknown.
