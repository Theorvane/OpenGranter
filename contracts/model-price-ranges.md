# Exact advertised price range discovery

GET /api/v1/models accepts optional min_price/max_price for base prompt prices and min_output_price/max_output_price for base completion prices, in USD per million tokens. Bounds are inclusive and conjunctive. Published pricing.prompt/completion strings are per-token values; compare exactly after shifting each query bound down six decimal positions. Never use floating-point money arithmetic, average prompt/output prices for these filters, apply discounts/conditional overrides/optional charges or infer a request bill.

The accepted local query syntax is `(?:0|[1-9][0-9]*)(?:\.[0-9]+)?(?:[eE][+-]?[0-9]+)?`, bounded to 128 UTF-16 units and finite Number conversion. Number conversion checks the existing finite-input restriction only; exact comparisons and continuations retain the string, including positive underflow and zero with enormous exponents. Reject negative values (including -0), leading signs/zeroes, whitespace, incomplete decimals, nonnumeric/null/empty values, duplicates, oversized/nonfinite input and exactly reversed pairs. Local restrictions are not invented OpenAPI constraints. SDK number serialization may already lose precision before a request reaches the gateway.

Reuse bounded sparse decimal digits with BigInt positions. Query bounds are prepared once per request, with no exponent-sized zero runs/powers or cross-request cache. Equivalent spellings compare equal. Models without pricing metadata cannot match any selected range; known zero remains a valid free base price. Omitted ranges preserve existing listing order and behavior.
