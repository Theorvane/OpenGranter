# Opt-in audit review page (#784)

`mountManagementAudit(root)` starts disconnected and makes no requests. The trusted owner explicitly connects the bounded #782 `createManagementAuditClient`; the connection itself is not authentication. The owner must clear immediately on logout, identity/permission change or expiry, and dispose on unmount. Do not auto-connect this page to SSO or use ambient cookies. Existing server authentication, current IAM and mandatory audit remain required per page.

Apply sends exact principal/model text without trimming or normalizing. Blank means omitted. Time controls explicitly represent UTC; invalid or reversed ranges clear prior records without transport. Each query uses limit 25. First page removes continuation; next page uses the exact returned cursor and the submitted (not edited draft) filters. Every query immediately clears prior records. Superseded responses and detached button callbacks cannot restore data. Clear resets filters, client and records; dispose permanently empties the root.

Only fixed event ID, UTC time, kind, request ID, principal ID and model metadata columns are rendered with textContent. Arbitrary details, credentials, policy payloads and transport/error bodies are not rendered. Empty, invalid-query, denial, unauthenticated, cancelled and unavailable outcomes have distinct fixed messages. This component trusts only the bounded validated audit client result, not arbitrary HTTP JSON.

This source-only opt-in view does not modify the public entry, grant authority, enable a session, retain content, export CSV or complete #642 / installed acceptance. Lifecycle timers and session/CSRF/IdP decisions remain the integration owner's responsibility.

Previous page retains only submitted query/cursor metadata, not event rows; it always re-fetches through the bounded client with fresh server authentication, IAM and mandatory audit. Edited but unapplied controls cannot alter navigation scope. History is committed only with the latest successful response and removed on loading/failure, invalid or new filters, first page, clear and dispose. Detached controls cannot replay prior navigation.

Current-page CSV: Prepare current-page CSV performs a fresh bounded list read of the submitted filters and cursor, not edited draft controls or cached rows. It clears prior rows and any download immediately; only the latest ready response may create a Blob download link. Export includes only event_id, time_utc, kind, request_id, principal_id and model, using the shared formula-safe CSV encoder. At most 25 rows (or header-only for empty) are exported; no automatic pagination, arbitrary details, credential IDs or policy versions. This is not full-history/server CSV parity. New queries, invalid filters, clear, replacement and dispose revoke the Blob URL. Detached links cannot perform a valid download. The trusted owner must still clear on expiry/permission changes; files already saved by the user cannot be recalled. Browser Blob support failures produce the fixed unavailable state without rows/downloads. The build adds only the exact pure src/export/csv.ts encoder to its dependency allowlist, not its directory or new server entry points.

## Audit row scope drilldown (#637 / #642)
Each ready metadata row offers Filter audit by this principal, and Filter audit by this model only when an allowlisted nonempty model alias is reported. The action performs a fresh bounded read through the connected client, not local filtering of cached rows. It replaces only the selected dimension of the submitted query, preserves the other submitted dimension and UTC bounds/page size, removes the cursor and backward history, and synchronizes controls from that submitted scope (discarding unapplied drafts). Exact identifiers remain textContent and query values, never HTML or URL fragments.

Loading immediately removes prior rows, controls and any CSV Blob link; denial/unavailability keep no records or row actions. Duplicate clicks and detached row controls cannot dispatch after a newer render, connect/clear or disposal. This does not create a new audit session or mount the audit view in the SSO workspace. The trusted owner must still clear on expiry/logout/permission change; per-request server IAM and mandatory read audit remain required. Existing browser build restrictions are unchanged: the view is bundleable but audit-client.ts still imports server-side projection validators outside the approved public-source allowlist; a reviewed public validator extraction/contract is required before a public browser audit-client bundle. Native smoke may use a runner-owned bounded client bridge and must disclose that boundary.
