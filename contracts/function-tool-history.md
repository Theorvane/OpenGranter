# Function Tool Result History Contract

Both non-streaming chat prefixes accept an assistant message with one to 128 function `tool_calls` followed by exactly one `tool` message for each call ID. An empty `tool_calls` array with string assistant content remains an ordinary text-history message and is forwarded without pending results. Each call has a nonempty unique string ID, `type: "function"`, and a nonempty function name plus serialized string arguments. IDs, names and argument strings are copied before asynchronous work and forwarded exactly to direct OpenAI or delegated OpenRouter. Assistant content may be string, null or omitted; omitted content normalizes to null. Tool-result content may be a string or a nonempty array of exact text parts; text parts concatenate to one string. Existing system/developer/user/ordinary assistant text behavior remains.

A `tool` message requires a nonempty `tool_call_id` matching a pending call in the immediately preceding assistant call group. Results may arrive in any order within that group. Duplicate, orphan, missing or unresolved results reject. A user, assistant or instruction message cannot interrupt pending results. Invalid roles, fields, call shapes and content reject at the HTTP boundary before route selection and in native invokers before credential lookup. Direct Anthropic/Gemini reject even valid tool history before secrets until native mapping is designed.

IAM, model and final-provider authorization, limits, audit and usage run for each model request, including continuation. Tool IDs, names, arguments and results never enter metadata audit, operational logs or errors. A completed model attempt records usage; a failed upstream attempt retains possible-billing accounting. The gateway never executes the function itself. Streaming, server tools, multimodal tool content, native Anthropic/Gemini translation, provider-specific extensions and full external-client conformance remain open under #116.

Sources: https://openrouter.ai/openapi.json and the installed OpenAI SDK request types, reviewed 2026-09-30.
