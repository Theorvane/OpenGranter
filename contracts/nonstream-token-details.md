# Nonstream token usage detail subset

Direct OpenAI and delegated OpenRouter preserve optional prompt_tokens_details and completion_tokens_details under normalized usage on both chat bases. Omission remains omitted; null containers, empty objects and zero counters remain exact. Prompt fields cached_tokens/cache_write_tokens/audio_tokens/video_tokens require nonnegative safe integers; completion fields reasoning_tokens/audio_tokens/accepted_prediction_tokens/rejected_prediction_tokens additionally permit explicit null. These local bounds are stricter than the source integer type.

Capture recognized values once into immutable plain snapshots. Unknown keys are ignored, never forwarded. A malformed container or recognized value omits only that detail group; preserve the other valid group and aggregate accounting. An omitted group is unavailable information, not a zero count or certification that categories were complete. No values, subset relationships or totals are inferred from details.

Existing aggregate normalization and missing/partial/invalid/reported classifications remain unchanged. Details alone cannot manufacture usage. Compatible /api/v1 still omits incomplete usage as a whole, while /v1 retains sparse normalized counters. Categories may overlap or exceed base counts; never sum them into totals, add another ledger record, or use them as provider-billed cost. Required audit/ledger persistence still precedes successful delivery; authentication, model/final-provider IAM/Deny and limits still precede dispatch. Unknown payloads, costs, prompt/response bodies and credentials stay out of operational records/errors.

Actual pinned OpenRouter/OpenAI SDK socket cases cover supported nonstream categories. Delegated final stream categories use the separate [stream contract](stream-token-details.md). Native Anthropic/Gemini mapping, detailed ledger reporting, cost/BYOK/server-tool fields and full external-client certification remain open. The version-15 ChatUsage source pin already tracks these inline properties, so this runtime change does not refresh it. Sources: [official schema](https://openrouter.ai/openapi.json), [API overview](https://openrouter.ai/docs/api_reference/overview). See [plan](../docs/plans/290-nonstream-token-details.md).

The [Gemini category extension](gemini-token-details.md) implements only the bounded native cached/reasoning counter subset on nonstream and text/function streams. Other native categories and detailed ledger/billing remain open.

The [Anthropic cache usage fix](anthropic-cache-usage.md) extends these historical rules for reported disjoint native cache counters: include them once in native prompt aggregates, retain cumulative input/cache values across omitted/null stream updates, and expose bounded client-only read/write details. It does not add projected details again, rewrite historical records, or establish billed cost.
