# Proxy user model discovery

GET /api/v1/models/user returns the existing compatible object:list/data/total_count/links.next envelope for enabled aliases visible to the authenticated OpenGranter principal. Apply model AND final inference-provider IAM with explicit Deny precedence, complete catalog validation/capture and mandatory private models-listed audit. General listing remains unchanged; this endpoint defaults to text output. Unknown/basic metadata cannot establish text output. Explicit all includes every authorized alias, including basic rows; other comma-separated output filters use existing bounded any-member matching.

Accept only offset, limit, output_modalities and the already-supported list sort subset. Reuse local unsigned safe-integer paging, limit 1..1000, modality syntax and stable exact-price/context/creation/benchmark ordering. Unsupported query fields, duplicate/invalid values and unsupported performance/popularity sorts return 400 after authentication and before catalog access. Unpaged raw requests return all visible results; supplying either paging field applies the existing 500 default limit when omitted. No user/principal selector is accepted.

Every continuation is a fixed relative /api/v1/models/user path containing only validated filters, sort and paging, including the explicit effective text default. It never becomes /models, a caller-controlled host or an upstream destination. Each page authenticates again, reloads catalog and current IAM and completes private audit; no cursor grants retained authorization. Capture rows/total/continuation before awaiting audit so source mutation cannot alter output. Required audit/corrupt hidden metadata/catalog failure suppresses success with existing safe 503 errors. No request body, inference, routing, secret, limit or usage port is read/called.

Reuse models-listed with only visible count and existing principal/credential/policy-version/request attribution. Existing denial/unavailable and anonymous authentication events remain content-free and use the shared PostgreSQL sanitizer/history without new event kinds or migrations. Prompts, credentials, query values, model metadata and requested identities never enter operational event bodies or client errors. All recognized Fetch/Node success/error/fallback outcomes use no-store; unsupported methods remain 404.

The exact compatible user collection path takes precedence over the OpenAI model parameter. Alternate percent encodings of that reserved compatible ID reject 400 after authentication. An exact local alias named user can still be read through /v1/models/user. The compatible count collection, general listing, legacy defaults and singular wrapped OpenRouter lookup retain their existing contracts. Reserved collection IDs are explicit restrictions of the OpenAI extension.

Installed OpenRouter 1.4.18 models.listForUser uses its explicit operation bearer, including on automatic next-page requests. Actual sockets cover both route kinds, rich-row iteration, caller isolation and fresh Deny. Its declared query type exposes offset/limit/outputModalities; raw tests additionally cover supported sort. Like general listing, the typed SDK requires rich metadata in each returned row: explicit all with a basic alias produces a measured client ResponseValidationError. Raw callers may consume that basic row; administrator metadata publication remains a release gate. Do not hide or fabricate missing metadata merely to satisfy the SDK.

This is local proxy-IAM discovery. It does not import OpenRouter account preferences, privacy/retention rules or regional endpoint eligibility, make live capability claims, or certify all user-list semantics. The [official OpenAPI](https://openrouter.ai/openapi.json), fetched 2026-10-25, defines listModelsUser and the four query objects with ModelsListResponse. The sixth [user-model source guard](user-model-schema.md) now selects this operation, its four query objects, explicit bearer security and response root/array/item definitions, alongside the existing shared metadata guard. Structural coverage does not establish all account-specific semantics. Full #116 and unresolved #7 remain open. See [plan](../docs/plans/524-user-model-discovery.md).
