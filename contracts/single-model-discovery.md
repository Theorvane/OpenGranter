# Compatible single model discovery

The separate [OpenAI-style retrieval contract](openai-model-retrieval.md) adds bare model reads through encoded plural-path parameters. It does not change this singular OpenRouter operation's wrapper, exact author/slug parser or required rich metadata. References below to unsupported plural paths concern literal author/slug hierarchies, not the new encoded single-parameter extension.

GET /api/v1/model/{author}/{slug} returns exactly {data: model} using the same rich captured metadata and id/object/created/owned_by projection as compatible listing. Match an exact enabled administrator-published alias author/slug. Explicitly published variant suffixes and safe Unicode names work, including SDK percent encoding. canonical_slug and alias_target remain informational: do not redirect them, look up an upstream model or grant additional route authority. A visible alias without rich metadata returns503 privately, while existing listing can still publish basic aliases.

Authenticate before interpreting lookup segments/queries or accessing the catalog. Recognize the compatible singular GET prefix only; decode exactly two nonempty segments once. Local limits are128 UTF-16 units for author and256 for slug. Reject dot segments, whitespace, C0/DEL/C1 controls and decoded slash/backslash/percent/question/hash, malformed encoding, extra/trailing segments and nonempty queries with400 after authentication and before catalog access. Browser URL normalization can remove dot segments before the handler; they never create a separate routing/lookup mechanism. Unsupported methods, legacy bases and plural paths remain404. Do not read request bodies. Recognized lookup responses, including auth/query/audit/unavailable/not-found errors, use no-store and server-owned request IDs.

Validate and capture the complete catalog, including hidden/disabled/out-of-result metadata. Use current enabled model/final-provider IAM with explicit Deny precedence before matching. Unknown, disabled and inaccessible aliases return the same fixed404 envelope after required model-read audit with count0. Successful reads require model-read audit with count1 before returning200. Current catalog/policy is reloaded for every request; multiple candidates do not duplicate a model. No provider, route, secret, limit, inference or usage ports are invoked.

Hidden malformed catalog, catalog failure and missing rich metadata on a visible target record model-read-unavailable with no details and return a fixed503. Required audit failure always suppresses details/status success. Build the projected result before awaiting audit so caller-owned alias/created/metadata mutation cannot alter output. Operational events/errors retain no requested identifier, raw path, query values, metadata, prompts/responses or credentials.

The PostgreSQL audit projector accepts only integer count0/1 for model-read, strips all other details and retains only authenticated attribution. model-read-unavailable retains no event-specific details. Existing migrated audit storage and principal-scoped history reuse the same sanitizer; malformed counts/storage faults fail safely. No migration or new management permission is introduced.
