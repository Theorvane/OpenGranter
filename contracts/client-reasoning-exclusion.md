# Delegated reasoning exclusion preference

Both chat bases accept optional reasoning.exclude true/false for delegated
OpenRouter nonstream and existing ordinary text streams. Preserve true, false and
omission exactly without injecting defaults or changing effort/summary aliases.
The immutable reasoning object may contain supported effort and summary together;
the existing equal/conflicting effort alias rules remain effective. Own undefined,
null, malformed types and unknown controls reject before routing or credentials.
Null semantics are undocumented and remain outside this local subset.

Capture exclude once and freeze the complete supported projection before async
work. Later caller mutation cannot change the upstream payload. Preferences grant
no provider/model/region or tool authority. All native structured configurations
remain unsupported before secrets; native shorthand support is unchanged.

Forward this preference to the approved upstream without local response filtering
or fabrication. Existing returned scalar reasoning and valid details are preserved
even if an upstream returns them despite exclude true. No summary/exclusion
precedence, encrypted-detail removal or exclusion guarantee is asserted. The
preference does not disable model reasoning or imply free/reduced usage. Preserve
actual aggregate accounting, unknown usage and safe possibly-billed failures.
Existing empty-string length responses remain successful. Missing/null content
without substantive reasoning/refusal still fails safely; broader no-content
success remains a separate response-contract gap under #116.

Authentication, complete model/provider IAM with explicit Deny precedence, limits,
required audit/usage and persistence-gated stream completion remain shared.
Prompt/history/response/preferences and credentials stay out of operational records
and errors. No ledger charge is inferred from the preference or returned details.

The [official reasoning guide](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens)
documents optional boolean exclusion and an upstream default of false; the gateway
does not insert that default. The guide shows exclusion alongside effort and
explains that reasoning is still billed. Current
[official OpenAPI](https://openrouter.ai/openapi.json) and pinned OpenRouter SDK
1.4.18 expose only effort/summary inside reasoning. Actual SDK sockets confirm
exclude is stripped, while the OpenAI-compatible SDK forwards the raw extension
through both bases and modes. This is a documented HTTP extension with explicit
source/SDK gaps, not complete SDK compatibility. Pin v18 is unchanged and cannot
certify an absent field. Null, summary interactions, broader budget/legacy controls,
native mappings, tool streams and full external-client certification remain open.
