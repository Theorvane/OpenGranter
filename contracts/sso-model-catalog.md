# Internal SSO user catalog reads

Refs #637, #641. `createPostgresSsoModelCatalog` accepts the registered-key RFC 9068 configuration, a migrated PostgreSQL query client and a mandatory `writeAudit` callback. This is a trusted server-only composition, not a public API, browser transport, session issuer or catalog administration API.

- `list(accessToken, requestId)` yields `{state: 'ready', data: [...]}`.
- `detail(accessToken, requestId, exactAlias)` yields `{state: 'ready', data: model}` or `{state: 'missing'}`. Hidden, disabled and absent aliases are indistinguishable.
- Models contain `id`, `object: 'model'`, `created`, and `owned_by: 'opengranter'`. An explicit informational extension ([plan](../docs/plans/641-sso-display-publication.md)) publishes optional administrator-registered `name` (nonblank, at most 256 code units), `description` (at most 8192), and `context_length` (null means unknown; otherwise a nonnegative safe integer). Legacy rows omit them. An optional `pricing` object contains only exact administrator-published `prompt` and `completion` USD-per-token base-price strings ([plan](../docs/plans/641-sso-base-prices.md)); no computed bill, discount, override or provider price lookup is implied. Legacy metadata-less rows omit it. Optional `architecture` contains only published `input_modalities` and `output_modalities`; optional `supported_parameters` contains published parameter labels ([plan](../docs/plans/641-sso-capability-display.md)). Each is a unique array of at most 64 nonblank strings of at most 128 code units; empty arrays remain empty and metadata-less legacy rows omit them. This publication is not verified capability. They do not contain canonical/upstream IDs, candidates, credential references, private architecture details or other rich metadata. These fields are not routing/capability authority.
- Each call verifies the signed token/current active-human binding, reads complete current IAM including inherited role policies, and reads the validated catalog. Existing `llm:InvokeModel` on `model:<alias>` and `llm:UseProvider` on the final inference provider determine visibility; explicit Deny wins. These are existing user-discovery semantics, not a grant of `catalog:Manage` or a new administration read permission.
- Detail reads only its parameterized exact-alias publication with the same row validation; it does not scan the list or inherit its 1,000-model collection bound. An unrelated malformed publication cannot poison a valid detail. The requested publication still fails closed if malformed. List behavior and its bound are unchanged.
- Separate binding, IAM and catalog reads do not provide atomic revocation. No cache or proxy-token exchange is used. No inference, limits reservation or usage record is performed for these read-only operations.
- Authentication failure yields `unauthenticated`; authentication/snapshot/catalog failures yield `unavailable`. Errors contain no source text. Every result awaits mandatory audit; callback failure replaces the result with `audit_unavailable`, never data.
- The audit callback receives a frozen projection: operation, server-owned request ID, outcome, result count, and authenticated principal/policy-version references (or null attribution for authentication failure). It receives no credentials, claims, requested alias or private error. Request IDs must be generated by the trusted HTTP adapter, never copied from client headers. The callback owns trusted timestamps and durable persistence.

## Activation gate

A real HTTP/session adapter, request validation, no-store response mapping, durable SSO-specific audit storage, and reviewed runtime composition remain required. The existing gateway audit table requires a proxy credential for authenticated attribution; **do not fabricate a credential ID or strip the actor to fit it**. This factory intentionally cannot activate that table or bind a listener. Local signed test JWT/PGlite acceptance does not certify an installed PostgreSQL server, company IdP, browser session or provider call.
