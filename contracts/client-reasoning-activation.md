# Delegated reasoning activation preference

Both chat bases accept optional reasoning.enabled true/false for delegated
OpenRouter nonstream and existing ordinary text streams. Preserve exact booleans
and omission without injecting effort, defaults or model capability assertions.
Supported optional summary and exclusion may be forwarded alongside activation
without local interpretation of their precedence. Null, own undefined, malformed
types and unknown controls reject before routing or credentials.

Supplied enabled with any nested effort (including null), or a forwarded named
reasoning_effort, is outside this local bounded subset pending raw-chat interaction
clarification. This is a local scope restriction, not an official conflict rule.
Existing top-level null/omission normalization remains unchanged; normalized-away
shorthand with activation is accepted. Effort-only requests and their existing
alias rules remain unchanged when enabled is absent.

Capture each preference once, compare only captured values, and freeze before
async work. Late mutation and accessor failures cannot alter the forwarded body
or expose private error text. Activation preferences grant no model/provider/region
or tool authority. Native structured configurations remain unsupported before
secrets; this change does not implement native thinking activation.

Forward to the approved delegated destination without local response filtering,
reasoning fabrication, generated-content guarantees or free/reduced usage inference.
If an upstream returns reasoning despite enabled false, existing validated fields
and actual accounting remain unchanged. Authentication, complete destination IAM
with explicit Deny precedence, limits, required audit/usage and persistence-gated
stream completion stay shared. Operational records/errors exclude preferences,
history, prompts, responses and credentials. Safe failed possibly-billed outcomes
and existing unknown/no-content response semantics remain effective.

The [official reasoning guide](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens)
documents default activation and maps disabled native thinking to enabled false.
Omitted activation/effort and mandatory support vary by model; no default is added
locally. Raw-chat effort interactions, null and summary/exclusion precedence are
not settled here. Current [official OpenAPI](https://openrouter.ai/openapi.json)
and pinned OpenRouter SDK 1.4.18 omit enabled. Actual SDK sockets confirm stripping,
while the OpenAI-compatible SDK forwards the raw extension through both bases and
modes. Unchanged pin v18 cannot certify an absent field. Broader budget controls, native mappings,
tool streams and complete external-client certification stay open under #116.

Optional positive-safe-integer budget is covered by [its separate contract](client-reasoning-budget.md).
Budget with any nested effort, forwarded named shorthand or supplied enabled stays
outside that local subset pending source clarification; outer output caps stay unchanged.

Legacy inclusion aliases are supported by [their separate contract](client-legacy-reasoning.md).
A supplied raw configuration together with the flag remains outside that local subset;
canonical configuration behavior is unchanged.
