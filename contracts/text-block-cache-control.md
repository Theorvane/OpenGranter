# Explicit text block cache control contract

Issue #444. Plan: [444-text-block-cache-control](../docs/plans/444-text-block-cache-control.md).

Both /v1 and /api/v1 accept non-null optional cache_control={type:"ephemeral",ttl?:"5m"|"1h"} on text parts. Delegated OpenRouter preserves arrays across system/developer/user/assistant/tool histories; managed Anthropic maps instruction/user/assistant blocks with complete unmarked function results. Both support nonstream and text/refusal/function streams. Retain the complete frozen array when any supported marker exists, including exact Unicode/whitespace strings and unmarked empty parts. Unmarked/null-OpenAI-marker-only client arrays retain prior literal concatenation. TTL omission remains omission; no beta header or provider eligibility change is added.

Capture root/indices/type/text/cache directive/type/TTL once before credentials. Reject null/malformed/extra/prototype directives, missing/unknown type, unknown/null TTL, rich/refusal/prediction directives and empty marked text. Retained messages have at most 128 text parts. At most four block directives across the entire history are allowed; 1h markers must precede effective 5m markers. Omitted TTL counts as 5m only for ordering, without inserting a field. These are local delegated restrictions following native Anthropic limits, not structural constraints invented in the source pin. Explicit OpenAI marker write/window semantics stay independent.

Reject simultaneous request cache_control, root prompt_cache_options or prompt_cache_breakpoint anywhere with block directives before routes/credentials; mixed-format precedence/conversion remains unimplemented. Native OpenAI/Gemini reject block directives before secrets without format/resource substitution. Native Anthropic rejects tool-result marked arrays before secrets and at its exported converter: SDK shape permits nested text directives, but effective partial caching is unverified and promoting a marker would move its boundary.

Native Anthropic instruction arrays become system text blocks, with a plain newline separator block between instruction messages. Caller text and markers remain on their original blocks; prior all-string instructions remain one newline-joined string. Separate blocks are not guaranteed to be token-equivalent to the old string. User/assistant parts retain their shape; correlated assistant tool_use blocks follow the text parts, and complete unmarked adjacent tool_result strings retain their existing grouping. Unknown upstream model/empty-block/size constraints may still fail safely; acceptance does not prove caching.

Authentication, full approved model/final-provider/host IAM/Deny scope, limits, secret references, required audit/usage before final delivery, missing usage and possibly-billed failure/cancellation stay shared. Preferences and private text remain outside operational records/errors and synthetic response echoes. Jev opt-in disclosure retains exact joined text without directive metadata/object coercion. Preserve reported-only aggregate/cache-category accounting; never infer hits, retention, savings, usage or provider-billed cost.

The unchanged version-28 pin already tracks ChatContentText, ChatContentCacheControl and directive/TTL targets (32 fields/22 request-history definitions). Offline integrity and fresh fixed-host structural comparison apply without pin/projector changes. OpenAI 7.23.0 and OpenRouter 1.4.18 fixtures exercise controlled sockets across both bases/routes/modes. Native tool-result partial caching, directives on tool definitions/rich content, mixed automatic/explicit controls, other native formats, live certification, full #116 and unresolved #7 remain open.
