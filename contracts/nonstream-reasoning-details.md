# Nonstream reasoning details

Direct OpenAI and delegated OpenRouter preserve optional reasoning_details arrays, including empty arrays, at assistant messages through both chat prefixes and actual OpenAI/OpenRouter SDK sockets. Null and malformed arrays reject. The bounded item union supports reasoning.summary with required string summary, reasoning.encrypted with required string data, and reasoning.text with optional string/null text and signature. Common metadata is optional string/null id and format plus a safe integer index, including negative indices because the official schema encodes no minimum. Unknown format strings are opaque, preserving the source's extensible enum behavior. No value is parsed, decrypted, verified or treated as authenticated authority.

Copy arrays and scalar records into immutable values, preserving order, omission and explicit nulls. Own undefined values, sparse arrays, unknown keys/types and server-tool-call items reject rather than silently dropping or executing semantics. These are explicit local subset restrictions. Existing refusal/filter/function-call and finish-reason rules still apply. Stop/length completions may have null/missing content independently of a substantive detail payload; missing content normalizes to null. Valid empty/null payloads and signature/id/format/index-only metadata are preserved without granting authority. Malformed content or incompatible tool/finish semantics still reject. No new array/string cap or fabricated default is introduced.

Malformed details after dispatch fail with fixed upstream errors and possibly-billed failed-attempt usage. IAM, explicit model/provider Deny, limits, required audit/ledger and safe missing usage retain existing behavior. Metadata audit, ledger and errors exclude detail payloads/signatures/IDs, prompts/responses and credentials. This does not change provider-billed cost into estimated cost or invent missing token counts.

Sources: [official schema](https://openrouter.ai/openapi.json) and [reasoning guide](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens). The source union also contains reasoning.server_tool_call, tracked by the separate schema-drift work, but this runtime subset rejects it. Delegated assistant history replay is implemented under [its contract](client-reasoning-details-history.md). Structured reasoning request controls, native Anthropic/Gemini thinking/signatures, direct/tool streaming and complete reasoning/client conformance remain open. Delegated text-stream details use the separate [stream contract](stream-reasoning-details.md). See [plan](../docs/plans/284-nonstream-reasoning-details.md).

The SDK permits content and detail fields independently; optional-content stop/length follows the contracts below. Use only the once-captured immutable detail snapshot for projection; inherited fields are not projected and do not grant authority. Detail-only output preserves one successful usage record when usage exists, unknown missing usage and required persistence failures that suppress delivery. Opaque encrypted data is neither decrypted nor authenticated. See [follow-up plan](../docs/plans/302-detail-only-reasoning.md).

Length-only null/missing content is now independently supported by [its contract](no-text-length.md), without a substantive reasoning payload. Stop optional content now follows its separate contract; malformed-field validation remains unchanged.

Optional stop content follows [its contract](no-text-stop.md), independent of substantive reasoning. Inherited fields stay unprojected; malformed fields, unsupported finishes and history-input guards remain effective.
