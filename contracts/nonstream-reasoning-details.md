# Nonstream reasoning details

Direct OpenAI and delegated OpenRouter preserve optional reasoning_details arrays, including empty arrays, at assistant messages through both chat prefixes and actual OpenAI/OpenRouter SDK sockets. Null and malformed arrays reject. The bounded item union supports reasoning.summary with required string summary, reasoning.encrypted with required string data, and reasoning.text with optional string/null text and signature. Common metadata is optional string/null id and format plus a safe integer index, including negative indices because the official schema encodes no minimum. Unknown format strings are opaque, preserving the source's extensible enum behavior. No value is parsed, decrypted, verified or treated as authenticated authority.

Copy arrays and scalar records into immutable values, preserving order, omission and explicit nulls. Own undefined values, sparse arrays, unknown keys/types and server-tool-call items reject rather than silently dropping or executing semantics. These are explicit local subset restrictions. Existing refusal/filter/function-call and finish-reason rules still apply. Stop/length completions may have null/missing content when at least one validated detail contains nonempty summary, text or encrypted data; missing content normalizes to null. Empty/null payloads and signature/id/format/index-only metadata do not grant this success path. Malformed content or incompatible tool/finish semantics still reject. No new array/string cap or fabricated default is introduced.

Malformed details after dispatch fail with fixed upstream errors and possibly-billed failed-attempt usage. IAM, explicit model/provider Deny, limits, required audit/ledger and safe missing usage retain existing behavior. Metadata audit, ledger and errors exclude detail payloads/signatures/IDs, prompts/responses and credentials. This does not change provider-billed cost into estimated cost or invent missing token counts.

Sources: [official schema](https://openrouter.ai/openapi.json) and [reasoning guide](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens). The source union also contains reasoning.server_tool_call, tracked by the separate schema-drift work, but this runtime subset rejects it. Reasoning details in requests/history, native Anthropic/Gemini thinking/signatures, direct/tool streaming and complete reasoning/client conformance remain open. Delegated text-stream details use the separate [stream contract](stream-reasoning-details.md). See [plan](../docs/plans/284-nonstream-reasoning-details.md).

The SDK permits content and detail fields independently; the nonempty payload guard is a local supported-subset constraint rather than an upstream prohibition on metadata-only outputs. Use only the once-captured immutable detail snapshot for success and projection; inherited fields cannot grant unprojected success. Detail-only output preserves one successful usage record when usage exists, unknown missing usage and required persistence failures that suppress delivery. Opaque encrypted data is neither decrypted nor authenticated. See [follow-up plan](../docs/plans/302-detail-only-reasoning.md).
