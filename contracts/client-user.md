# Client end-user request metadata contract

Issue #428. Plan: [428-client-user](../docs/plans/428-client-user.md).

Both /v1 and /api/v1 accept optional non-nullable string user for managed OpenAI/delegated OpenRouter nonstream/stream text/refusal/function requests. Omission omits the field; preserve empty, whitespace, Unicode and exact case without coercion/trimming/hashing. Null and other types reject safely before route/credential work. This is the current OpenRouter/installed SDK subset; OpenAI HTTP nullable user remains outside it. Existing HTTP body size bounds apply. Native Anthropic/Gemini supplied values reject before credentials rather than silently translate to metadata.user_id or labels.

Capture the field once at each request boundary before asynchronous credentials. Forward only through the existing registered fixed hosts and IAM-approved model/provider scope. Client user is upstream attribution metadata; it cannot replace authenticated principal ID, credential ID, policy versions, permissions or limits. Operational records/errors/responses cannot include the supplied identifier. Required usage/audit handoffs, safe possibly-billed opened failures, cancellation and no fallback after emitted output retain existing behavior. No usage/cost counters or response metadata are derived from the identifier.

Version 21 selects exactly 26 request fields, adding the user schema and required status without modifying prior definitions/maps. Type/nullability/default/required/bounds/extension changes are structural drift; annotations remain ignored. Missing/malformed user source fields or rehashed invalid exact maps fail safely. Source refresh must verify prior selections and source/projection digests. Full runtime/model/client certification, native attribution mappings, safety_identifier/prompt_cache_key, registration APIs, full #116 and unresolved #7 remain open. Sources: [OpenRouter OpenAPI](https://openrouter.ai/openapi.json), [user tracking](https://openrouter.ai/docs/cookbook/administration/user-tracking), [OpenAI](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create).
