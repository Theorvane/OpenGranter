# RFC 9068 SSO management access-token verifier

Plan: [488-sso-token-management](../docs/plans/488-sso-token-management.md).

createRfc9068SsoAccessTokenVerifier({ issuer, audience, jwks, now }) returns verifyAccessToken(token). Administrator configuration is captured once and projected into a private local public-key snapshot; request data cannot select trust configuration. Configured issuer is exact HTTPS without userinfo/query/fragment/whitespace, 1–2048 UTF-16 units. The API audience is an exact opaque 1–256-unit identifier. jwks has 1–16 own indexed public RSA keys with unique own kid values; keys have own kty/n/e/kid and only optional own alg/use/key_ops. Reject private/unknown own key fields, noncanonical base64url integers, unsupported signing metadata and RSA moduli outside 2048–4096 bits. Missing metadata projects to RS256/sig/verify. No key/header URL fetch, discovery or request-provided key import occurs. Invalid config/getters throw InvalidSsoAccessTokenConfiguration / Invalid SSO access token configuration without raw data or cause.

Tokens are bounded nonempty opaque strings up to 16384 UTF-16 units without NUL/ill-formed Unicode. Real jose signature verification permits RS256 only and local matching public keys; ambiguous/missing key selection rejects rather than trying every key. RFC media-type semantics accept at+jwt case-insensitively with optional application/ prefix, rejecting ID/generic JWT types. Require iss/sub/aud/exp/iat/jti/client_id plus the confirmed local auth_time restriction. Exact configured issuer and audience membership apply; audience arrays have at most 64 nonempty bounded identifiers. Subject/client_id/jti are 1–256-unit well-formed non-NUL strings. Extra claims/header key URLs confer no identity or policy authority.

NumericDates are finite nonnegative numbers; fractional dates are supported. Require exp > iat, exp-iat <= 3600 seconds and auth_time <= iat. Optional nbf must be valid and precede exp. With one captured current millisecond clock (converted to whole epoch seconds by jose), jose applies 60-second tolerance to expiry, future iat/nbf and a maximum 3600-second age since iat. Duration bound receives no extra skew. auth_time describes original end-user login and may precede refreshed issuance; no maximum login age is imposed. Clock must be a nonnegative safe integer representable as a Date.

Valid verification returns only a frozen { issuer, subject }. Invalid/malformed/unsupported/expired tokens return undefined without exposing raw token, claims, library errors or causes. Clock/unexpected verifier failures throw SsoAccessTokenVerificationUnavailable / SSO access token verification unavailable. Local key snapshots do not refresh: rebuild a verifier to add/remove keys and overlap registered keys for manual rotation. No introspection, jti replay cache or access-token revocation mechanism is introduced.

The contributor selected RFC 9068, local RS256 public keys, one-hour limits/60-second tolerance and required auth_time on 2026-10-11. RFC auth_time is optional, not generic human-grant proof. Administrators must trust an issuer that emits this claim only for actual end-user authentication; tokens without it reject under this local profile. Existing active-human binding and current IAM remain additional requirements. This module neither grants management policy nor exposes a public HTTP/authentication-audit contract. See [RFC 9068](https://www.rfc-editor.org/rfc/rfc9068.html#section-2.2) and [JWT confusion guidance](https://www.rfc-editor.org/rfc/rfc8725.html#section-3.12).
