# Public managed OpenAI function streaming

Activate the trusted native function stream port on both chat bases and generate it from stored native registrations in direct/dual PostgreSQL servers. Preserve authentication, complete model/final-provider IAM, limits, Jev/order selection, accounting/audit gates, no replay and cancellation. Both installed SDKs must complete two interleaved calls and correlated tool-result continuation on both bases with fresh Deny, persistence errors, unknown usage and abort. Keep exact native model IDs and rich/custom/server-tool/other-native-provider gaps open.

This bounded internal stage preserves fixed destinations and captured scope.
Managed text is already activated; this stage activates managed function streams without claiming full #116 compatibility.

## Acceptance cases

- OpenAI 7.23.0 and OpenRouter 1.4.18 complete two interleaved indexed function calls and correlated tool-result continuation through both bases; each request gets fresh authentication/model/provider IAM and limits.
- Explicit Deny, authentication, limit and required selection audit stop native keys. A managed function port cannot activate an unwired delegated function route.
- Required accounting or outcome-audit failure after argument delivery produces a safe error without success DONE or inference replay. Unknown usage stays missing, and SDK abort cancels native upstream response while recording one failed billed attempt.
- Persisted direct/dual servers generate registered native function adapters, ignore runtime adapter overrides, preserve per-attempt metadata-only records and re-evaluate stored Deny before additional keys.
- Completed calls are response content only: no call IDs/arguments, prompts, result bodies or credentials in operational audit/accounting.

Exact upstream IDs remain required. Custom/server tools, multimodal calls, native Anthropic/Gemini functions and automatic model snapshot equivalence remain separate release gates under #116.
