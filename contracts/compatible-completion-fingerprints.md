# Compatible completion fingerprint projection

For normalized nonstream object:chat.completion responses, both /v1 and /api/v1 add system_fingerprint:null when native output omits/has undefined fingerprint. Null explicitly represents unavailable protocol metadata, not a fabricated backend identity, provider assertion or determinism guarantee. Supplied exact string/null values remain intact.

The managed and delegated success boundaries apply this after required accounting/outcome audit, using a cloned compatible completion. Recorded usage and original upstream/accounting metadata remain unchanged. Native Anthropic/Gemini nonstream completions now explicitly represent an unavailable fingerprint as null on both bases for installed SDK tool/text continuation conformance; see [Anthropic client functions](anthropic-client-functions.md) and [Gemini client functions](gemini-client-functions.md). Generic handler results without the completion discriminator remain unchanged. SSE and error envelopes do not use this projection. Malformed native fingerprints still fail under existing possibly-billed upstream failure handling.

Exact pinned official SDK socket tests verify omitted upstream fingerprints now deserialize as null on both bases, including two-request managed OpenAI/delegated function-result workflows. IAM/limits, required audit/ledger failures and operational metadata privacy remain shared. This addresses one nonstream schema gap only; discovery, streaming fingerprint null restrictions and full external-client conformance remain open. Sparse compatible nonstream usage is handled separately by [the usage projection contract](compatible-completion-usage.md).
