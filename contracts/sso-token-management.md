# Internal SSO token-management service

Plan: [488-sso-token-management](../docs/plans/488-sso-token-management.md).

`createPostgresSsoTokenManagementService({ client, now, verifyAccessToken })` exposes `issue({ accessToken, requestId, principalId, expiresAt })` and `revoke({ accessToken, requestId, credentialId })` to trusted internal application code. It returns existing one-time issued credentials or the existing revocation result. It exposes no HTTP route. createPostgresRfc9068SsoTokenManagementService wires the real [RFC 9068 verifier](sso-access-tokens.md) from administrator issuer/audience/public-key configuration and the same clock. The configured factory captures its five own required settings once, ignores extra authority and reports invalid/missing/getter-failed configuration through the fixed InvalidSsoAccessTokenConfiguration error.

The trusted access-token verifier returns an already verified `{ issuer, subject }` or `undefined`. Only verified identities reach the [binding reader](sso-identity-bindings.md); exact current active human bindings derive the actor ID. The configured verifier enforces the selected RFC 9068 profile and required auth_time restriction; decoding a JWT or accepting caller-supplied claims is not verification. Injected verifiers are trusted internal deployment code, not request data. Proxy tokens and ID tokens are not management access tokens. The registered issuer must use auth_time only for actual end-user authentication; this local restriction is not universal human-grant proof.

Capture all own required operation fields once before any verifier/SQL await. Extra actor IDs, kind/active state, policy statements/versions, owner and verification claims are ignored. Access tokens are opaque strings of 1–16384 UTF-16 units; metadata IDs are 1–256. Reject NUL/ill-formed Unicode, preserve exact spelling and require a nonnegative safe-integer expiry. Invalid inputs throw `InvalidSsoTokenManagementInput` / `Invalid SSO token management input` before verification or SQL.

Verifier rejection and missing/inactive/service/unbound identity throw `SsoManagementUnauthenticated` / `SSO management unauthenticated`. Verifier throws, malformed verified identity and binding failures throw `SsoManagementAuthenticationUnavailable` / `SSO management authentication unavailable`. Both are fixed errors without raw tokens, claims, driver messages or causes. An error thrown by an injected verifier is always a dependency failure, even if it has a domain-error name. Failed authentication reads no actor policies, writes no token-management decision and performs no credential or lifecycle mutation. Public authentication auditing is still a separate contract.

After authentication, the [existing management service](token-management.md) reloads current actor policies and enforces `iam:Manage` on the stored credential owner or requested issuance principal. Implicit/explicit Deny, required authorization decision audit, owner-kind lifetime caps and atomic lifecycle writes remain unchanged. Authentication supplies no permissions, extra audit kinds, secrets, inference or usage calls. Neither access tokens nor issuer/subject claims are included in management decisions/lifecycle events; only existing nonsecret actor/target/request/credential/policy identifiers appear. Issued raw proxy tokens return once under the existing contract.

Each operation re-verifies its access token and reloads binding/kind/active and policy state; no authentication cache. Request mutation during verification/SQL cannot change the captured operation. Changes between calls take effect. Binding and policy reads are separate and state changes after a read are not transactionally revalidated. Audited administrator provisioning, public API paths/errors/audit, automatic JWKS rotation/introspection/replay controls and full release gates remain pending.

The reusable [SSO human authenticator](sso-human-authentication.md) now owns the verification/binding stage. Existing operation ordering and safe error constructors are preserved, including gateway-module re-exports; this refactor adds no public HTTP behavior.
