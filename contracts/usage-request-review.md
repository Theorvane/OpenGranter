# Request-scoped usage review

Depends on the existing request filter API contract (PR934), not a new endpoint. JSON and CSV clients accept optional requestId using the exact 1–256 ASCII grammar in usage-request-filter.md. The review state snapshots requestId before await and retains it with opaque page cursors and CSV. JSON rejects any cross-request record even if its principal/model matches. CSV preserves server bytes; the existing server selection is authoritative.

Usage has a Request ID input and a row action, View attempts for this request. The action preserves current principal mode and applied model/time restrictions, resets pagination, clears old rows during loading, and uses fresh IAM plus mandatory audit. It never promotes a self read into explicit-target ReadAll. Unapplied input drafts do not change applied bounds. Empty, invalid, unavailable and denied states retain existing behavior; identity disposal aborts and suppresses stale controls/responses. It shows one authorized page, not every attempt globally, cost totals or a retry determination.

Local acceptance includes production clients/review over owned Node HTTP, signed synthetic RFC9068 access tokens and migrated embedded PostgreSQL; principal/request intersections, exact punctuation, keyset continuation, CSV, fresh Deny and failed durable audit. DOM-port tests verify action, loading, scope preservation, empty/error and stale-control cleanup. No real browser login/session, external IdP, installed PostgreSQL, TLS/deployment URL or provider certification is implied. No session/CSRF/schema/activation changes.
