# Delegated streaming reasoning content

Both client bases preserve optional string/null reasoning in validated delegated OpenRouter deltas. Omission stays omitted; null, empty, Unicode and embedded newlines remain exact. Reasoning-only deltas and reasoning with ordinary content/refusal are response content, serialized as one safe JSON SSE frame with the authorized client alias. No request-side reasoning option or new upstream destination is introduced.

The decoder and independent client encoder reject malformed reasoning with fixed safe errors. The encoder captures delta reasoning once and validates usage-only reasoning before incomplete-token early returns, so injected substantive content cannot silently disappear. The existing bounded SSE event size applies to the entire frame. A final usage-only event may contain absent/null/empty reasoning but cannot contain substantive reasoning: such a frame fails rather than dropping content. Synthesized final usage never repeats previous reasoning. Unsupported reasoning_details, encrypted blocks, tools and other rich fields remain rejected.

Existing authentication, model/final-provider IAM, limits, selection audit, per-attempt usage and required outcome audit stay in order. Malformed first chunks produce safe JSON failure; malformed later chunks terminate with the path's safe SSE error and no terminal success. Failed dispatched attempts remain possibly billed and are never replayed. Missing usage stays unknown. Cancellation and progressive backpressure use the existing delegated HTTP composition.

No reasoning transcript enters completed sequence summaries, audit events, ledger metadata, logs or error messages. This is a response projection; it does not enable protected content storage or change its explicit auditing policy. Official SDK 1.4.18 socket tests on both bases preserve delta.reasoning with complete/missing usage and includeUsage:false; success does not certify full reasoning compatibility.

Non-streaming/native reasoning, reasoning_details/encrypted formats, request controls, aggregation and full external-client workflows remain open. The reviewed ChatStreamDelta pin already selects optional string/null reasoning, so no pin refresh is required. See [plan](../docs/plans/238-stream-reasoning.md), [delivery contract](delegated-http-stream.md) and [official schema](https://openrouter.ai/openapi.json).
