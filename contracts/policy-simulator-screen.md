# Persisted policy simulator screen (#640)

`mountManagementPolicySimulator(root, options)` is a disconnected TypeScript screen. It has no public mount or network endpoint. `connect({ read, expiresAt })` attaches a host-owned trusted reader until an absolute millisecond deadline; this is a display lifecycle, **not** a server permission grant. A `PolicySimulationReader` accepts exact `{ principalId, action, resource }` and an AbortSignal. It returns ready/decision, missing, denied, unauthenticated or unavailable. The host must independently authorize/scope/durably audit every server read once the public reader contract is agreed. Do not put SQL clients or the server simulator into a browser bundle.

- Initial/disconnected: sign-in message, no editable fields. There is no global reader, token acquisition/storage, cookie, fetch URL, SSO/session adapter, permission choice or auto-connect.
- Active: accessible labelled exact principal/action/resource fields; 256/512/512 character limits, nonempty values and no ASCII controls. No trimming, wildcard expansion or hypothetical policy inputs. Invalid submissions never call the reader. Enter submits the form. Loading disables further submissions; explicit Cancel aborts and suppresses late completion. A later deliberate simulation is a new read, not an automatic retry.
- Ready: display the submitted exact principal/action/resource, Allow/Deny, normalized reason and evaluated policy IDs/versions, with the permanent warning that IAM Allow does not grant execution and does not simulate catalog, limits or provider checks. No invoke control exists.
- Project results at runtime: coherent effect/reason, at most 1024 unique policy IDs and bounded nonempty IDs/versions. Inactive/unresolved decisions require empty versions. Unknown keys, raw policy statements, reader errors and stack traces never render. All user/result strings use textContent, never HTML. Invalid result becomes unavailable.
- Missing principal has a separate non-grant state. Denied/unauthenticated removes the reader and all drafts/results until a fresh trusted connection. Errors preserve editable input for manual retry but remove any prior decision.
- `clear()` must run for logout/identity/permission changes and page lifecycle, and `dispose()` on unmount. These remove reader, drafts/results, abort work and invalidate detached controls. Replacement, cancellation, expiry and disposal suppress stale responses, including readers ignoring abort. Expiry uses the trusted clock and asynchronous scheduler; bad clocks, failed scheduling and failed timer cleanup cannot retain diagnostic authority. Stale timer callbacks cannot clear a replacement reader. No memory-zeroization claim.
- Default clock/scheduler are Date.now/setTimeout; custom schedule must invoke asynchronously and return cancellation. A host must not treat a UI deadline as access control, nor bypass session/reader/audit decisions to connect it.

## Executable evidence

`test/management-policy-simulator-app.test.ts` exercises the screen through structural DOM controls and the supported self-contained browser build, without expanding server-source build allowances. Actual migrated PGlite plus existing createPostgresPolicySimulator supply current inherited Allow, changed explicit Deny/version, inactive/missing principals and a database failure. Other cases cover invalid fields/results, text injection, stale forms/results, cancellation, replacement, logout, expiry, bad clocks and failed scheduling/cleanup. Existing simulator tests also compare persisted decisions to the PostgreSQL gateway IAM boundary.

This is not a native-browser or login test, authenticated public simulator API, installed PostgreSQL or full UI acceptance. Existing frontend entry, workspace navigation, runtime/listener, schema and deployment remain unchanged. Public simulator reader visibility, authentication, mandatory access audit and host integration remain **undecided and disconnected** per [persisted simulator contract](persisted-policy-simulator.md).
