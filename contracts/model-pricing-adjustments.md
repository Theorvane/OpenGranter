# Informational model pricing adjustments

Issue #484. Plan: [484-model-pricing-adjustments](../docs/plans/484-model-pricing-adjustments.md).

Complete model pricing snapshots require own prompt/completion and may include own optional discount (finite number) and overrides (non-null array of 0..64 non-null known-field objects). Each override optionally supplies seven non-null price strings: prompt, completion, audio, input_audio_cache, input_cache_read, input_cache_write and input_cache_write_1h; finite numbers min_prompt_tokens, utc_start and utc_end; and utc_days with 1..64 open strings, each 0..256 UTF-16 units. Every override field is optional, so empty rows are valid. Preserve exact values, spelling, empty/duplicate override rows, duplicate days and array order. Do not infer numeric ranges, defaults, normalization or sorting.

Price strings retain the existing nonnegative decimal/scientific grammar and 128-unit bound, with finite numeric conversion; they are never converted for billing. The official schema's utc_days minItems=1 is enforced even though installed SDK1.4.18 accepts empty day arrays. Local length/count/own-required/unknown-key restrictions are explicit; SDK accepts broader arbitrary price strings and strips unknown fields.

Supplied own undefined/null, wrong/nonfinite scalar types, unknown fields, holes (even with inherited fillers), missing own base prices and excessive bounds reject privately. Capture each own scalar/nested value and validated array length once, then inspect bounded own indices without invoking supplied iterators. Deeply freeze pricing, override objects/arrays and day arrays before asynchronous handoffs. Inherited optional fields are omitted and getter failures remain private.

Only compatible rich discovery exposes adjustments after full hidden-catalog validation, enabled model AND final-provider IAM, existing query/order/paging and required private audit; each page reevaluates current policy. Basic/legacy rows remain unchanged. No pricing data enters operational errors/events, and listing calls no inference/routing/secret/limit/usage ports.

Adjustments are administrator-published information. Discovery does not match time/day/token conditions, apply discounts or inherited prices, choose/rank providers, estimate billed costs, fetch pricing or certify accuracy/freshness. PostgreSQL list/route boundaries share validation/frozen capture while keeping approved routes and the nullable JSONB object/64 KiB aggregate cap. No migration/backfill is needed; independently valid maximum field/array bounds may exceed that storage cap. Downgrades require removing newly supported fields.

OpenRouter1.4.18 maps inputAudioCache/inputCacheRead/inputCacheWrite/inputCacheWrite1h/minPromptTokens/utcDays/utcStart/utcEnd; OpenAI7.23.0 preserves raw extra fields. Public/storage/SDK tests cover success, Deny, failures and boundary capture. Existing three pins stay unchanged. Publication/refresh, pricing application policy, full #116 and unresolved #7 stay open. Sources: [official schema](https://openrouter.ai/openapi.json), [models reference](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties).
