# Bounded predicted text output contract

Issue #436. Plan: [436-predicted-output](../docs/plans/436-predicted-output.md).

Both /v1 and /api/v1 accept nullable optional prediction={type:"content",content:string|[{type:"text",text:string}]} on managed OpenAI/delegated OpenRouter nonstream and text/refusal streams. Null/omission omits the upstream field. Preserve exact empty/whitespace/Unicode/long under-body-bound strings, empty arrays and text-part order; do not join parts, trim or coerce expected content. Capture/freeze required own root/part fields and arrays once before credentials; reject malformed/non-record/extra fields and more than 128 parts. The count bound is an explicit local restriction, not an encoded source limit. Existing complete HTTP body bounds apply.

The conservative portable subset excludes normalized supplied tools/tool choices/parallel controls and probability controls, including empty arrays/none/false; function history, positive frequency/presence penalties and non-null max_completion_tokens also reject before routes or credentials. Existing nullable unset controls retain their normalization. Capture the completion alias once for both combination validation and output-limit resolution. Nonpositive penalties, existing max_tokens and administrator caps preserve normal passthrough, but the official guide does not discuss max_tokens compatibility and no universal guarantee is made. Native Anthropic/Gemini supplied predictions reject before secrets without assistant-prefill/models.predict translation; null/omission preserves defaults. Registered model eligibility is unchanged; the provider may reject unsupported model/control combinations under existing safe failure handling.

Expected text is private client content, never IAM authority, prompt history, a cache preference, a synthesized response or a usage counter. Exclude it from operational records/errors and request-field echoes; actual upstream response text may naturally match the prediction and is delivered normally. Preserve independently reported accepted_prediction_tokens/rejected_prediction_tokens as existing informational response categories; never derive aggregates, savings or billed cost from expected text/categories or subtract rejected prediction tokens. Missing usage stays missing. Authenticated attribution, complete approved model/final-provider IAM/Deny, limits, fixed hosts, required audit/ledger before final frames, safe possibly-billed failures and cancellation remain shared.

Version 25 adds only prediction plus whole Prediction/PredictionContentText (30 fields/18 request-history definitions). Preserve exact nullable root, required type/content, string/text-array union and required text-part fields without invented count/length/extra-key/default constraints. Track transitive type/enum/nullability/required/default/bounds/extensions even with unchanged parent refs. Ignore annotations; reject missing/malformed source targets, stale versions and rehashed invalid exact maps. Removing these selections reproduces version 24 canonically; fresh source/projection provenance is reviewed. Installed SDK fixtures certify captured request/delivery/error paths, not live Predicted Outputs, model support or latency/billing improvement. Rich parts, broader combinations, native mappings, live certification, full #116 and unresolved #7 remain open.
