# Delegated client reasoning effort

Both chat prefixes accept optional reasoning_effort as max, xhigh, high, medium, low, minimal or none for delegated nonstream and text streaming. Null/omission inject no field or default. Capture once before credential resolution; preserve exact supplied strings and the same approved upstream model/provider scope. Existing output-token/sampling/tool-history controls stay independent. Effort is not a strict token budget or authenticated authority.

Invalid strings, types, case and unknown structured reasoning controls reject before routing with fixed safe errors. Direct OpenAI nonstream maps supplied non-null effort; Anthropic/Gemini still reject it before credentials. IAM, explicit Deny, limits, required audit/ledger, safe provider errors and usage outcomes remain shared. Effort fields, prompt/response bodies and credentials stay outside operational records/errors.

Fresh [OpenRouter OpenAPI](https://openrouter.ai/openapi.json) and pinned SDK define seven strings including max, null and no default; the parameter overview's shorter list is not treated as a narrower enum. Actual SDK sockets cover reasoningEffort wire mapping and raw OpenAI JSON forwarding. Model support differs. Structured reasoning.effort is rejected as a whole, so conflicting dual-field precedence is not inferred; verbosity remains an independently forwarded control in integrated builds. Full reasoning request/history/response coverage, other native mappings and structural drift selection remain gaps. See [plan](../docs/plans/274-reasoning-effort.md).

## Direct OpenAI native mapping

The [current Chat Completions reference](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) and installed OpenAI SDK 7.23.0 declare all seven string values plus null. OpenGranter forwards supplied strings exactly as top-level reasoning_effort to the registered fixed OpenAI host; null/omission omit the field as the local contract. Capture once before credential resolution, including getter-backed or mutated inputs. No effort/default alias or model-specific capability rule is invented. Model subsets and defaults differ; provider rejection stays a fixed safe error with failed, possibly-billed attempt accounting. Effort stays outside audit/ledger/errors and preserves independent tools, history and generation controls.

Direct streaming and Anthropic/Gemini effort mappings remain unsupported. Structured reasoning/include_reasoning and raw thinking/history/response-token-detail compatibility are not added. Raw private reasoning is not made available by this request control; see the [reasoning guide](https://developers.openai.com/api/docs/guides/reasoning). Pending compatible reasoning-response work remains a separate feature. See [plan](../docs/plans/278-openai-reasoning-effort.md).
