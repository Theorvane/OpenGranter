# Delegated client reasoning effort

Both chat prefixes accept optional reasoning_effort as max, xhigh, high, medium, low, minimal or none for delegated nonstream and text streaming. Null/omission inject no field or default. Capture once before credential resolution; preserve exact supplied strings and the same approved upstream model/provider scope. Existing output-token/sampling/tool-history controls stay independent. Effort is not a strict token budget or authenticated authority.

Invalid strings, types, case and unknown structured reasoning controls reject before routing with fixed safe errors. Native direct adapters reject supplied non-null effort before credentials until explicit mappings are implemented. IAM, explicit Deny, limits, required audit/ledger, safe provider errors and usage outcomes remain shared. Effort fields, prompt/response bodies and credentials stay outside operational records/errors.

Fresh [OpenRouter OpenAPI](https://openrouter.ai/openapi.json) and pinned SDK define seven strings including max, null and no default; the parameter overview's shorter list is not treated as a narrower enum. Actual SDK sockets cover reasoningEffort wire mapping and raw OpenAI JSON forwarding. Model support differs. Structured reasoning.effort is rejected as a whole, so conflicting dual-field precedence is not inferred; verbosity remains an independently forwarded control in integrated builds. Full reasoning request/history/response coverage, native mapping and structural drift selection remain gaps. See [plan](../docs/plans/274-reasoning-effort.md).
