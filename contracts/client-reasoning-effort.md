# Delegated client reasoning effort

Both chat prefixes accept optional reasoning_effort as max, xhigh, high, medium, low, minimal or none for delegated nonstream and text streaming. Null/omission inject no field or default. Capture once before credential resolution; preserve exact supplied strings and the same approved upstream model/provider scope. Existing output-token/sampling/tool-history controls stay independent. Effort is not a strict token budget or authenticated authority.

Invalid strings, types, case and unsupported nested reasoning controls reject before routing with fixed safe errors. Direct OpenAI nonstream maps supplied non-null effort; Anthropic and unsupported Gemini values still reject it before credentials. IAM, explicit Deny, limits, required audit/ledger, safe provider errors and usage outcomes remain shared. Effort fields, prompt/response bodies and credentials stay outside operational records/errors.

Fresh [OpenRouter OpenAPI](https://openrouter.ai/openapi.json) and pinned SDK define seven strings including max, null and no default; the parameter overview's shorter list is not treated as a narrower enum. Actual SDK sockets cover reasoningEffort wire mapping and raw OpenAI JSON forwarding. Model support differs. Nested reasoning.effort is rejected, so conflicting dual-field precedence is not inferred; summary-only objects are supported under [their contract](client-reasoning-summary.md); verbosity remains an independently forwarded control in integrated builds. The current version-17 pin tracks reasoning_effort structural drift. Full reasoning request/history/response coverage and other native mappings remain gaps. See [plan](../docs/plans/274-reasoning-effort.md).

## Direct OpenAI native mapping

The [current Chat Completions reference](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) and installed OpenAI SDK 7.23.0 declare all seven string values plus null. OpenGranter forwards supplied strings exactly as top-level reasoning_effort to the registered fixed OpenAI host; null/omission omit the field as the local contract. Capture once before credential resolution, including getter-backed or mutated inputs. No effort/default alias or model-specific capability rule is invented. Model subsets and defaults differ; provider rejection stays a fixed safe error with failed, possibly-billed attempt accounting. Effort stays outside audit/ledger/errors and preserves independent tools, history and generation controls.

Direct streaming and Anthropic effort mapping remain unsupported; the Gemini thinking-level subset is supported. Structured reasoning/include_reasoning and raw thinking/history/response-token-detail compatibility are not added. Raw private reasoning is not made available by this request control; see the [reasoning guide](https://developers.openai.com/api/docs/guides/reasoning). Compatible scalar and summary/text/encrypted reasoning responses are implemented under the [response contract](nonstream-reasoning.md); request forwarding does not certify native thinking/history semantics. See [plan](../docs/plans/278-openai-reasoning-effort.md).

## Direct Gemini thinking-level subset

The [Google REST thinking documentation](https://ai.google.dev/gemini-api/docs/generate-content/thinking) declares lowercase minimal, low, medium and high at generationConfig.thinkingConfig.thinkingLevel. Forward those exact strings after single pre-secret capture; null/omission add no thinkingConfig or default. Preserve output caps, sampling and stop/format controls. Reject none, xhigh and max before secrets; minimal does not guarantee thinking is disabled. This bounded direct subset does not implement OpenRouter level aliases or Gemini 2.5 thinkingBudget. Per-model support/defaults vary; invalid native model combinations retain fixed safe errors and possibly-billed failed accounting.

Generated thought:true parts and malformed thought flags fail with safe upstream errors and failed attempt usage even when no effort is supplied. Absent/false flags remain visible text; this does not implement thought summaries, signatures, history or thinking-token usage details. Effort/thought text/configuration and credentials stay out of operational records/errors. Existing authenticated destination scope, Deny, limits and required ledger/audit remain effective. See [plan](../docs/plans/280-gemini-reasoning-effort.md).

Anthropic reasoning-effort mapping remains unresolved: the [OpenRouter reasoning guide](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens) documents manual budget and native output effort paths, while [verbosity](https://openrouter.ai/docs/api_reference/parameters) already maps to output_config.effort. Do not infer precedence, budget rounding/defaults or adaptive-thinking capability from these overlapping descriptions.
