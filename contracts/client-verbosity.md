# Delegated client verbosity

Both chat prefixes accept optional verbosity as low, medium, high, xhigh or max for delegated nonstream and text streaming. Omission and explicit null supply no upstream field; null is a local compatibility allowance. No medium default, coercion or case conversion is injected. Capture once before asynchronous credential resolution and forward the exact validated scalar with the same fixed upstream model/provider scope. Existing sampling, tool history and output controls remain independent.

Unknown strings, booleans, numbers, objects and arrays reject before routing with safe client errors. Direct OpenAI forwards low/medium/high at top level and rejects xhigh/max before secrets; direct Anthropic maps all five levels to output_config.effort; native Google Gemini rejects supplied non-null values before secret access/dispatch until its mapping is implemented. Null/omission supply no native field or injected default. Authentication, explicit Deny, model/provider IAM, limits, required audit/ledger gates and usage outcomes remain shared. Request values, prompt/response content and keys remain outside operational logs, audit, usage and errors.

The [official parameter docs](https://openrouter.ai/docs/api_reference/parameters) document five values, but current official ChatRequest and pinned OpenRouter SDK omit the field. Actual OpenAI SDK raw JSON forwarding is covered; pinned OpenRouter SDK stripping remains an explicit external-client gap. No fabricated schema selection or full compatibility claim. Upstream model support, Google mapping, native thinking/rich responses, managed streaming and source drift selection remain open. See [plan](../docs/plans/268-client-verbosity.md).

Direct OpenAI chat mapping follows the [official OpenAI chat contract](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) and pinned SDK; model support differs. Both public bases and actual OpenAI SDK sockets preserve exact values and existing output/sampling/tool history controls. Single capture protects credential-await requests; denial, limits, required accounting/audit and safe possibly-billed upstream failures remain covered. See [direct mapping plan](../docs/plans/270-openai-verbosity.md).

Direct Anthropic top-level effort follows the [stable effort contract](https://platform.claude.com/docs/en/build-with-claude/effort) without a beta header or thinking setting. Preserve the existing version header and registered output cap. Levels are model-dependent; existing non-text/thinking response blocks still fail safely with possibly-billed accounting. No silent block dropping or complete thinking-model compatibility claim. See [Anthropic mapping plan](../docs/plans/272-anthropic-verbosity.md).
