# Nullable Client Logit Bias Contract

Both compatible chat prefixes accept omitted/null logit_bias or an object mapping own string token keys to finite numeric biases. Exact string keys and numeric values, including empty/Unicode keys, empty objects, zero and values outside provider-specific common ranges, are preserved. The selected official OpenRouter schema specifies nullable object with numeric additional properties and no key pattern or value bounds. Native non-JSON objects and non-finite/non-numeric values reject. HTTP malformed values reject before route selection; native malformed values reject before credential lookup.

Direct OpenAI and delegated OpenRouter forward a captured immutable map. Direct Anthropic/Gemini reject any supplied non-null map, including an empty one, before credentials or transport. Null follows omission and does not inject native defaults. Existing authorized-candidate fallback may continue under its own route-kind and IAM scope; this field adds no new capability routing or prompt rewriting.

Bias keys and values are untrusted request protocol data, not authenticated identity, IAM policy, model/provider selection, audit attribution or usage identity. Keep them out of metadata audit, operational logs and errors. Safe failed-attempt accounting remains. Per-model support and actual upstream validity are not guaranteed. The current selected source-drift pin does not include logit_bias; expand it in a separate reviewed pin revision. Full tool/stream/client conformance remains open.
