Anthropic/Gemini supplied tiers reject before secrets pending distinct native mappings; omission/null remain accepted. Preserve fixed approved model/host/provider.only and selected final-provider enforcement.

Do not infer model eligibility, latency, SLA, discounts, billed prices or actual served tiers from request preferences. Existing aggregate accounting and estimate/billed distinctions remain shared; no tier values enter operational audit/usage/error records.

## Direct Anthropic capacity mapping (#534)

Both client bases now accept normalized `service_tier:"auto"|"default"` on registered direct Anthropic requests across nonstream/text/refusal/function streaming. Map `auto` to native `auto`; map explicit `default` to native `standard_only`, restricting that request to standard capacity. Omission/null still omits the upstream field, with no inserted tier or change to native defaults. This supersedes the earlier blanket Anthropic supplied-tier rejection only. The native literal `standard_only` remains outside the public normalized enum; other recognized Anthropic tiers still reject before credentials. Managed OpenAI, delegated OpenRouter and Gemini retain their existing subsets and endpoint-scope constraints.

The shared direct transport validates the captured primitive before credentials and the common native body builder performs the two-value mapping. Text/function stream invokers reuse it. Preserve the registered Anthropic host, approved upstream model, output cap and2023-06-01 header; do not add beta headers, native speed mode, region selection or new provider authority. Default/auto admission changes no catalog eligibility or final-provider IAM. Existing approved destination evaluation, limits, mandatory audit/usage before final delivery, missing usage, possible billing, failures and body cancellation remain shared.

Request preferences do not prove the actual served tier, priority eligibility, latency, SLA, price or available capacity. Do not synthesize client `service_tier` or operational metadata from the requested value. Native served-tier response projection is implemented separately in #536 below; this request mapping does not infer it. Tier fields/native strings, private text and credentials remain outside operational events/errors and synthetic response echoes.

[Anthropic's service-tier guide](https://platform.claude.com/docs/en/api/service-tiers) and [Messages API](https://platform.claude.com/docs/en/api/http/messages/create), checked2026-10-25, document native `auto` and `standard_only`. Auto can use available priority capacity and otherwise other capacity; standard-only excludes priority. These are capacity controls, distinct from native fast-mode `speed`. No API-version upgrade, live inference, model/capacity guarantee or billed-cost certification is performed. Existing six source pins, dependencies, migrations and event/accounting schemas remain unchanged. Installed OpenAI7.23.0 and OpenRouter1.4.18 sockets exercise both normalized values and null through both bases against controlled native JSON/SSE upstreams. ## Reported Anthropic response tiers (#536)

Registered direct Anthropic JSON responses project an own usage.service_tier into root service_tier for text/refusal/function results. Preserve exact strings (including empty and future strings), explicit null and absence according to the existing compatible nullable-string response contract. Nonstring/non-null selected values fail with the established fixed private upstream error and possible-billing accounting; never echo rejected values. No field is inferred from request preferences, model names, counters, headers or prices.

Native text/function SSE consumers capture only the primitive metadata separately from token/cache counters. Initial and later usage reports follow latest-supplied precedence: omitted/undefined reports retain the previous value; explicit null replaces it. Content deltas contain no tier. Only a successfully completed summary/final compatible metadata frame exposes the retained value, after mandatory audit/usage. Persistence failure, malformed late metadata and cancellation withhold pending metadata and terminal success through existing failure paths.

The shared compatible text/function SSE encoder preserves a supplied tier even when token counters are absent or incomplete, omitting the numeric usage object in that frame. Tier-only reports cannot manufacture counters, cost or billed-price evidence; existing ledger missing-usage status remains explicit. This encoder rule applies to all compatible routes while native projection in this change is limited to Anthropic. Tier values stay outside operational events/errors/usage records; protected content-audit policy is unchanged.

Both bases and installed OpenAI7.23.0/OpenRouter1.4.18 SDK sockets exercise controlled native JSON/SSE. Preserve request admission and approved destinations, authentication/IAM/Deny, limits, required persistence and cache accounting. No pin, dependency, API-version, migration or operational schema change is introduced.
