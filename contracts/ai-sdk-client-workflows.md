# OpenRouter AI SDK Client Workflows

Issue [#538](https://github.com/Theorvane/OpenGranter/issues/538). Plan: [538-ai-sdk-workflows](../docs/plans/538-ai-sdk-workflows.md).

## Measured client surface

Pin development-only @openrouter/ai-sdk-provider 3.1.0, ai 7.0.153 and zod 4.6.6 on Node 22.14. Use createOpenRouter with an explicit gateway baseURL and a proxy token, then its chat model with generateText/streamText. Actual sockets cover /v1 and /api/v1, delegated OpenRouter and registered direct OpenAI/Anthropic/Gemini. Text completion and a streamed function execution/result continuation preserve fixed approved destinations and per-attempt accounting. The client runs a deterministic fixture tool; the gateway never executes it.

Set maxRetries:0, an abort deadline and a bounded two-step tool loop in probes. Test fetch permits only the local gateway chat endpoint and a bounded request count. Gateway upstream transports remain mocked at their registered approved hosts. No caller request or response is rewritten to make the SDK succeed. Negative persistence probes may observe a response clone; ordinary success/cancellation paths consume the original streaming response normally.

## Correlated tool-result names

The actual provider adds name to tool-result messages. Accept this optional measured client extension only when an own supplied string exactly equals the function name of the still-pending tool_call_id in the immediately preceding assistant call group. Capture once before asynchronous routing and remove the redundant name from the immutable internal message. Omission remains valid; own undefined, null, nonstring, empty/mismatching names and orphan/duplicate/unresolved results fail safely before routing or credentials. Results may arrive in any order within the group. Inherited names are not projected or used as authority.

Removing the validated hint prevents native adapters from interpreting it as an unsupported speaker name. The internal ChatMessage shape and native/delegated upstream history formats are unchanged. Non-tool speaker names keep their existing provider restrictions. The official ChatToolMessage projection does not declare this property; existing source pins remain byte-identical. This is a measured client extension, not a fabricated change to the official schema.

## Controls and measured limits

Authentication, fresh model/final-provider IAM with explicit Deny, limits and required selection/outcome audit and usage remain shared. Preflight failures cannot execute a client tool or access provider credentials. A tool result continuation must authenticate and evaluate fresh policy again; an initial allowed tool may execute locally before a later request is denied. Streamed content can already have been delivered when persistence fails. Required persistence failures withhold the actual final usage/DONE frames; do not interpret a client-synthesized finish-step after an error as a server success acknowledgment.

Client abort after content records a failed possibly-billed attempt and interruption audit without final server usage. Actual tool IDs, names, arguments, content and credentials stay out of operational records/errors. No limits, usage or pricing values are inferred from client summaries.

When provider counters are absent, the pinned client presents zero token totals while the server ledger retains missing/null counts. Incomplete native Gemini counters are preserved as partial/null totals in the ledger. Both /v1 and /api/v1 now omit incomplete usage under #540 and this client displays zero; the previously measured legacy sparse-usage parser failure is resolved without inventing counts. Success probes use explicitly reported complete native totals, never invented counts. The client zero default remains a measured limitation rather than a server accounting rewrite; the measured nonstream fingerprint gap is resolved separately by #542, while other client schema gaps remain separate.

These probes do not certify model discovery, signed Gemini calls, images, reasoning, embeddings/completions/responses/Decisions APIs, live providers, other client versions or full #116. Jev #7 remains unresolved. Existing OpenCode/OpenAI/OpenRouter SDK contracts and signed-Google configuration remain separate. Primary source checked 2026-10-25: [OpenRouter-maintained provider](https://github.com/OpenRouterTeam/ai-sdk-provider); actual pinned installed code and socket measurements define this bounded result.

## Nonstream parallel continuations (#546)

Actual generateText also completes a two-request JSON function/result loop on both bases through delegated OpenRouter and all three managed native adapters. Two calls to the same function carry different arguments and stable IDs; controlled client execution finishes in reverse order, while exact native continuation assertions retain the correct call/result pairing. The gateway never executes the function. Native Gemini coverage here uses ordinary reported IDs without thought signatures; signed namespaces remain separately uncertified for this client.

Each request authenticates and evaluates current policy independently, checks limits and records its own usage identity. A provider Deny introduced for the second request prevents a second upstream/credential access even though both client functions already completed locally. Initial auth/implicit/model/provider Deny, limits and selection-audit failure prevent upstream execution. Outcome-audit or usage persistence failure withholds the initial tool response and prevents local execution. Outcome-audit failure can occur after a successful provider call and persisted successful usage record; a 503 is not proof that the provider did no work. No automatic client retries are permitted in these probes.

The pinned AI SDK asLanguageModelUsage computes totalTokens from input/output counters. Controlled OpenAI/delegated/Gemini responses with prompt 2/completion 3/reported total 7 therefore appear as 5 per step and 10 across two steps in the client, while unmodified HTTP responses and the server ledger preserve 7 per attempt. Native Anthropic supplies 2/3 and its existing adapter derives 5. Client aggregate totals must not replace server accounting or establish provider-billed cost. This is an observed client summarization limitation; no production counter behavior changes.

See [plan](../docs/plans/546-ai-sdk-nonstream-tools.md) and [reproduction](../docs/ai-sdk-conformance.md). Production code, six structural pins, dependencies and storage are unchanged. Full #116 and unresolved Jev #7 remain open.

## Inline PNG workflows (#550)

Pinned createOpenRouter with AI SDK generateText/streamText now exercises one application-owned canonical PNG between two nonempty text parts on both bases and all four route adapters. The client receives Uint8Array image data with explicit image/png, not an arbitrary URL. Exact captured upstream history preserves bytes, MIME and text/image order: compatible image_url for OpenAI/delegated OpenRouter, base64 source for Anthropic and inlineData for Gemini. No caller wire or response is rewritten. The client media-download hook accepts only an empty URL plan; the provider fetch accepts only the bounded local chat endpoint. These safeguards certify inline bytes without certifying the default client's handling of remote URLs.

Both nonstream/stream probes cover auth/implicit/model/provider Deny, limits and selection/outcome audit and usage failures. Admission failures make no provider call or secret lookup. Required persistence failure withholds the nonstream completion or actual final server usage/DONE on streams; client-generated finish events are not server persistence evidence. Image input bytes, surrounding prompt text and credentials stay outside operational records and public errors. Cancellation after streamed content interrupts the upstream, records a failed possibly-billed attempt and does not produce a client finish-step in these probes.

Success fixtures supply complete input/output counters and retain a normalized total of 3 per attempt in the server ledger. OpenAI/delegated/Gemini fixtures explicitly report total 3; native Anthropic uses its existing 2+1 aggregate normalization. The earlier client-summary accounting limitations still apply; image serialization does not establish provider-billed cost, image tokenization or model vision capability. No production code, pins, dependencies, migrations or audit/ledger schemas change.

This extends only the measured single inline PNG/text-input subset. Other MIME/count/size/detail controls retain their existing gateway contracts but are not all exercised through this client. Bounded image+tool continuations are measured separately under #556 below. Signed Gemini, remote/file media, output images, reasoning, other endpoints/versions, live providers and full #116 remain uncertified. Jev #7 stays unresolved. See [plan](../docs/plans/550-ai-sdk-inline-images.md) and [reproduction](../docs/ai-sdk-conformance.md#inline-png-reproduction-550).

## Structured object workflows (#552)

Actual pinned createOpenRouter with generateText/streamText and Output.object now exercises both bases through managed OpenAI and delegated OpenRouter. A Zod4 string-property object becomes the measured draft-07 schema with required answer and additionalProperties:false; the provider emits the exact name/description and strict:true wrapper. Captured upstream format/model/provider assertions preserve approved destinations without request/response rewriting. Native Anthropic/Gemini json_schema rejection remains pre-secret, with no provider dispatch or fabricated usage, in both streaming and nonstream modes.

A valid JSON object reaches result.output. Malformed JSON or a wrong answer type produces client-local NoObjectGeneratedError with the returned text, stop reason and token usage, while the gateway retains the successful completion/usage record. The gateway does not validate or repair JSON output. Default Zod object validation also strips an extra property in these probes, despite the advertised additionalProperties:false/strict:true request: the server text remains exact and only the client's parsed object drops the extra value. Neither forwarding strict nor a client object certifies full returned-instance conformance. Client exceptions can retain returned content; they are not safe gateway operational error payloads.

Auth/implicit/model/provider Deny, limits, required selection/outcome audit and usage failure remain shared. A nonstream persistence fault withholds the completion and produces the existing safe error. On streams, text may already have been delivered before required persistence fails; the server emits an error and withholds actual final usage/DONE, but this pinned SDK can still resolve result.output from that text. Its error parts must not be ignored, and a parsed object/finish event is not a server persistence acknowledgment. Outcome-audit failure may follow successful persisted provider usage; usage-write failure is not proof of no provider work.

Ordinary success/parse-failure streams consume the original response. Only finite negative persistence/native-rejection probes inspect a response clone for actual wire completion markers. Successful fixtures report 2/1/3 counters; server ledger remains per-attempt and client summaries do not establish provider-billed cost. Schema/body/credentials stay outside operational audit/ledger/public gateway errors. Source pins, dependencies, storage and production code are unchanged. This is one bounded object schema, not all Output modes, partial object semantics, native mappings, server enforcement, live provider support, other versions or full #116. Jev #7 stays unresolved. See [plan](../docs/plans/552-ai-sdk-structured-output.md) and [reproduction](../docs/ai-sdk-conformance.md#structured-object-reproduction-552).

## Inline-image tool continuations (#556)

Actual pinned generateText and streamText compose a single inline PNG/text input with a two-request function/result loop on both bases and all four registered adapters. Exact captured first and continued native history retains image MIME/bytes/text order and function IDs/names/arguments/results. Nonstream clients execute two parallel lookups in reverse completion order; streaming clients execute one read function. The gateway never executes those application-owned tools. The empty-only media-download hook, bounded local endpoint fetch, maxRetries:0 and abort deadline remain in force; no caller wire/response rewrite is used.

Each request authenticates and checks current model/final-provider policy and limits independently. Fresh failed authentication, implicit/model/provider Deny or limit exhaustion on the continuation prevents a second upstream dispatch/secret access, even after the first allowed tools have run. First-attempt successful accounting remains. These are dynamic policy/limit fixtures, not certification of a specific identity-provider session or rate-window implementation. Denied follow-ups cannot undo application side effects.

Required usage/outcome-audit failures are exercised on both first and second requests. First-request persistence failures withhold executable calls in these probes. Second-request failures can follow local tool execution and provider work; outcome-audit failure can follow a successful usage write. Nonstream failures withhold the completion. Stream failures emit a safe error and withhold actual final usage/DONE, although final text may already have reached the client. Client finish events or content alone are not persistence acknowledgments. Only finite negative probes inspect response clones; successful streams consume the original response normally.

Successful requests retain distinct ledger request IDs and private per-attempt counters. Existing nonstream client recomputation remains: two input2/output3 steps appear as total10 in the AI SDK even when the server retains reported total7 per attempt; native Anthropic normalization and these streamed fixtures retain total5 per attempt. Image/tool serialization does not establish image tokenization or billed cost. Image bytes, surrounding text, function payloads and credentials stay outside operational audit/ledger/errors.

All 160 new conformance cases pass without production, dependency, six-source-pin or storage changes. This composes only ordinary calls and one canonical PNG. Signed Gemini, remote/file media, richer image controls/outputs, other tools/versions/endpoints, live vision support and full #116 remain uncertified; Jev #7 remains unresolved. See [plan](../docs/plans/556-ai-sdk-image-tools.md) and [reproduction](../docs/ai-sdk-conformance.md#inline-image-tool-reproduction-556).


## Bounded Gemini root anchor metadata (#618)

Explicit strict:false Gemini schemas may carry root $anchor using the existing 1..64-character ASCII anchor grammar. Root anchors coexist with optional root $id and typed/nullable/union/local-reference roots; duplicate root/definition names reject before credentials. Named root references remain invalid recursive schemas; existing local root-$defs resolution is unchanged, with no fetching or nested-base changes. Immutable both-base HTTP, actual OpenAI SDK sockets and native captured streams retain the metadata. Nested non-definition anchors, malformed/dangling/cyclic refs, unused invalid definitions and strict/tool/Anthropic exclusions remain pre-secret failures. Depth16/shared20,000 visits/128 definitions and IAM/limits/accounting/persistence/privacy bounds remain. This supersedes earlier root-anchor exclusions only, not generated-output validation, equivalence or live/operational certification. Full #116 and unresolved #7 remain open.
