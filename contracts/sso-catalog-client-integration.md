# Explicit SSO catalog client integration

The separately named createSsoManagementCatalogClient and createSsoManagementCatalogSession factories use only GET /management/v1/models and its encoded-alias detail path. Their caller supplies an already authorized request port. They never create/store credentials, authenticate a browser, select an arbitrary URL, fall back to proxy endpoints, activate a session, or grant permissions. The lifecycle is a UI state machine, not an HTTP session.

The existing proxy factories retain /api/v1/models, reserved count/user rejection and published optional display metadata. SSO permits count/user aliases and validates navigable aliases, safe nonnegative integer creation timestamps and OpenGranter ownership. It projects only the basic fields and explicitly reviewed optional publication: name, description, context_length, pricing, architecture, supported_parameters and top_provider context_length/max_completion_tokens ([contract](sso-model-catalog.md)). These are already published by the SSO HTTP API, not a new API expansion. Legacy omission, explicit null (unknown), and zero remain distinct. A present top_provider must be a non-array object; each present bound must be null or a nonnegative safe integer. Malformed fields fail the entire page/detail. Copy and freeze known nested fields; exclude moderation, routing, upstream and arbitrary private fields. Informational prices/capability labels/bounds are not effective policy, quota, live capability or routing authority. The proxy projection remains unchanged. Shared bounded bytes, fatal UTF-8, cancellation/identity epochs and status-only errors remain enforced.

Tests distinguish restored unit/lifecycle coverage from a real loopback Node HTTP boundary with signed test JWT, migrated PGlite, fresh IAM and durable mandatory audit. Those results do not certify a company IdP, browser login, installed PostgreSQL, live provider or deployment. Existing follow-up stacks are preserved and require their own review/rebase; this integration does not approve them.
