# Single model discovery schema guard

A separate version1 fifth pin selects official GET /model/{author}/{slug}, operationId getModel, OpenAPI/document identity, complete author and slug path parameter objects, HTTP200 application/json root schema, and whole ModelResponse and Model definitions. Both path parameters are required:true with unconstrained string schemas in the reviewed source. Preserve complete serialization/default/bounds/nullability/extension data without inventing runtime encoding, length, exact-alias or IAM restrictions in the source pin.

ModelResponse is an object requiring data with a reference to Model. Select the entire Model object, including its full required list, properties, references and extensions. This independently tracks lookup identity/root/parent structure. Referenced metadata bodies such as PublicPricing and ModelLinks remain monitored by the separate existing model-response pin, which the CLI must always validate and compare alongside this one. Shared Model changes report both affected guards; metadata-body-only changes report the response guard. Unselected/future targets remain outside detection. No automatic graph expansion, remote reference retrieval or runtime instance validation follows.

Read inline operation parameters; require exactly one author and slug entry in path with explicit required:true and a nonempty schema object, without parameter references/content. Named selected path-level inheritance rejects for explicit review; unrelated inherited header references are not followed. Missing/malformed containers, duplicate/missing selected entries, changed location/optionality, referenced response objects, empty/malformed selected definitions, excessive depth and nonfinite structural values fail with fixed private errors. Empty or absent path-level parameter lists are valid. This is structural validation, not complete OpenAPI/JSON Schema semantic validation or reference resolution.

Pin validation requires an exact envelope/projection/parameter/definition map, version1, the fixed official URL, valid ISO retrieval date, canonical source/projection SHA-256 and fixed operation/success root reference. Rehashed malformed maps/unnormalized data reject; correctly rehashed valid reviewed changes are not a source signature. Editorial description/title/example/examples/externalDocs/$comment fields are stripped; annotation-named properties and literal default/const/enum/x-* extension data stay structural. Object-key/parameter order is normalized and structural array order retained.

Offline compatibility:check validates five pins without network. Explicit compatibility:drift validates all five before one fixed-host bounded HTTPS retrieval with omitted credentials and no supplied headers, redirect rejection and safe time/body limits. Compute every selected comparison before any success output, report each subset separately and exit nonzero for drift/unavailable/invalid input. Never write pins. Controlled CLI cases cover single-only parameter/root changes, shared Model changes, metadata-only existing-response changes, simultaneous five-subset drift, invalid fifth pin before fetch and invalid fifth source without partial success output. Previous four pin bytes remain unchanged.
